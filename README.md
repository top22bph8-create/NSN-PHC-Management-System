# ระบบบริหารงาน รพ.สต.บ้านหนองสนม

เว็บแอปบริหารงานภายใน (React + Vite + Tailwind + Firebase) เผยแพร่ผ่าน GitHub Pages

## ฟีเจอร์รอบที่ 1
- ล็อกอิน + สิทธิ์ตามบทบาท (Super Admin, ผอ., ธุรการ, การเงิน, พัสดุ, ควบคุมโรค, เวชปฏิบัติฯ, ผู้ดูรายงาน)
- Dashboard, ค้นหาแบบรวม, เลือกปีงบประมาณจากส่วนกลาง
- ทะเบียนหนังสือรับ/ส่ง: เพิ่ม แก้ไข ค้นหา กรอง ดูรายละเอียด แนบไฟล์ (PDF/Word/Excel/รูป) ลบพร้อมยืนยัน ส่งออก Excel/CSV
- เลขทะเบียนอัตโนมัติ (เช่น 001/2569) ตั้งรูปแบบได้ ขึ้นปีใหม่เริ่มใหม่
- Audit Log (ใคร ทำอะไร เมื่อไร ข้อมูลเดิม/ใหม่)
- โมดูลอื่นในเมนูแสดงเป็น "เร็วๆ นี้"

## ตั้งค่าครั้งแรก
1. อัปโหลดไฟล์ทั้งหมดขึ้น GitHub (ไม่รวม node_modules)
2. GitHub → Settings → Pages → Source เลือก **GitHub Actions**
3. Firebase Console → Firestore → Rules วางเนื้อหาไฟล์ `firestore.rules` → Publish
4. Firebase Console → Storage → Get started → Rules วางเนื้อหาไฟล์ `storage.rules` → Publish
5. Firebase Console → Authentication → Settings → User actions → **ปิด** "Enable create (sign-up)"
6. เข้าเว็บด้วยอีเมลเจ้าของระบบ ครั้งแรกระบบสร้างสิทธิ์ Super Admin ให้อัตโนมัติ

## เพิ่มผู้ใช้
สร้างบัญชีที่ Firebase Authentication → Add user แล้วเพิ่มสิทธิ์ในเมนู "ผู้ใช้งานและสิทธิ์"

## พัฒนาต่อในเครื่อง
```
npm install
npm run dev
npm run build
```

## ความปลอดภัย
- ห้ามใส่ข้อมูลผู้ป่วยหรือข้อมูลสุขภาพในที่เก็บโค้ดนี้ (เป็น Public) ข้อมูลทั้งหมดอยู่ใน Firebase
- ค่า `firebaseConfig` ใน `src/firebase.js` เปิดเผยได้ ความปลอดภัยอยู่ที่ Rules
- ข้อมูลผู้รับบริการ (เวชปฏิบัติครอบครัว) ยังไม่เปิดใช้ ต้องออกแบบสิทธิ์และ PDPA ก่อน

## เวอร์ชัน 2: โลโก้/ธีมฟ้าอ่อน, บุคลากร, วันลา, สำรองข้อมูล

1. อัปโหลดทับของเดิม: ลากโฟลเดอร์ `src` และ `public` ทั้งโฟลเดอร์ + `index.html` + `firestore.rules`
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ แล้วกด Publish
3. นำเข้าบุคลากร: ล็อกอินด้วย Gmail เจ้าของระบบ → "ทำเนียบบุคลากร" → "นำเข้า Excel"
   (ก่อนนำเข้าเปิด Authentication → Settings → User actions → Enable create (sign-up) และปิดกลับหลังเสร็จ)
4. ผู้ใช้ล็อกอินด้วย Username (เช่น 1) และรหัสผ่านตามไฟล์ แล้วระบบบังคับตั้งรหัสใหม่ (8 ตัวขึ้นไป มีตัวอักษรและตัวเลข)
   รหัสที่สั้นกว่า 6 ตัว ระบบต่อท้าย `#nsn` ให้อัตโนมัติ
5. ห้ามนำไฟล์ Excel ที่มีรหัสผ่านขึ้น GitHub

## เวอร์ชัน 3: ปีงบประมาณ 2570, เลขหนังสือส่งรูปแบบใหม่, เมนูใหม่, ยานพาหนะ/แผนงาน

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html`, `firestore.rules`, `storage.rules` ครบ
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ → Publish
3. Firebase → Storage → Rules: วางเนื้อหา `storage.rules` ใหม่ → Publish
4. ปีงบประมาณ: ระบบเริ่มนับตั้งแต่ปีงบประมาณ 2570 (1 ต.ค. 2569) เป็นต้นไป จะไม่มีปีเก่ากว่านี้ให้เลือก
5. เลขหนังสือส่ง: ออกเป็น "สน 51006.24/ลำดับ" อัตโนมัติ รันต่อเนื่องทั้งปีงบประมาณ
   - ถ้าลงวันที่ย้อนหลังและเลขที่นั้นถูกใช้ไปแล้ว ให้ติ๊ก "แทรกเลขที่ย้อนหลัง" ตอนเพิ่มหนังสือส่ง แล้วเลือกเลขที่เดิม ระบบจะออกเลขให้เป็น /20.1, /20.2 ตามลำดับ
6. เมนูใหม่: ทะเบียนควบคุมยานพาหนะ, แผนเวรนอกเวลาประจำเดือน, แผน/รายงานเยี่ยมบ้านเชิงรุกประจำเดือน (ตั้งค่าเลขทะเบียน/สิทธิ์เพิ่มเติมได้ที่หน้า "ตั้งค่าระบบ")

## เวอร์ชัน 4: เมนูรายงาน Excel/PDF, สมัครสมาชิกด้วยตนเอง, ทะเบียนหนังสือส่งช่อง "ถึง", ธีมฟ้าทันสมัย, วันลารายบุคคล

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html`, `firestore.rules`, `storage.rules` ครบ
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ → Publish (เพิ่มกฎอนุญาตให้ผู้สมัครใหม่สร้างโปรไฟล์ตัวเองสถานะรออนุมัติ)
3. **สำคัญ: เปิด Firebase Console → Authentication → Settings → User actions → "Enable create (sign-up)" ค้างไว้ถาวร** (ต่างจากเวอร์ชันก่อนที่ให้เปิดชั่วคราวตอนนำเข้ารายชื่อ) เพราะหน้า "สมัครใช้งาน" (/#/signup) ต้องใช้ฟังก์ชันนี้สร้างบัญชีให้ผู้ใช้เองตลอดเวลา
4. **สมัครใช้งาน/อนุมัติผู้ใช้**: ผู้ใช้ใหม่กดลิงก์ "ยังไม่มีบัญชี? สมัครใช้งาน" ที่หน้าล็อกอิน ตั้ง Username/รหัสผ่านเอง ระบบจะส่งคำขอเป็นสถานะ "รอผู้ดูแลระบบอนุมัติ" ไปที่เมนู "ทำเนียบบุคลากร" (มีแถบสีส้ม "รอสมัครใหม่" ให้สังเกตง่าย) ผู้ดูแลระบบเลือกบทบาทแล้วติ๊ก "ใช้งาน" เพื่ออนุมัติ หรือแก้ไข/ตั้งรหัสใหม่ได้ตามปกติ
5. **ทะเบียนหนังสือส่ง**: เลขที่หนังสือส่งที่จะออกแสดงในช่องแบบฟอร์มให้เห็นชัดเจนก่อนบันทึก และเปลี่ยนช่อง "ผู้รับ"/"ปลายทาง" เดิมเป็นช่อง "ถึง" แบบเลือกจากรายการที่กำหนดไว้ (พร้อมตัวเลือก "อื่นๆ" ให้พิมพ์เองได้)
6. **เมนูรายงาน**: แต่ละทะเบียน (หนังสือรับ/ส่ง, ยานพาหนะ, เวรนอกเวลา, เยี่ยมบ้าน) มีปุ่ม "รายงาน Excel" (ไฟล์ .xlsx ลายแถบสีแบบทะเบียนราชการ ดาวน์โหลดได้ทันที) และ "รายงาน PDF" (เปิดหน้าพิมพ์ในแท็บใหม่ แล้วใช้ฟังก์ชัน "พิมพ์" ของเบราว์เซอร์ เลือกปลายทางเป็น **"บันทึกเป็น PDF" / "Save as PDF"** — เป็นการพิมพ์ผ่านเบราว์เซอร์ ไม่ใช่ปุ่มดาวน์โหลด PDF โดยตรง เนื่องจากระบบนี้เป็นแอปฝั่งเว็บเบราว์เซอร์ล้วน ไม่มีเซิร์ฟเวอร์สร้างไฟล์ PDF)
   - หมายเหตุ: ตัวอย่างรายงานที่ส่งมา 8 แบบ มี 5 แบบ (คำสั่ง, ประกาศ, ใบสั่งซื้อ/สั่งจ้าง, สัญญาเงินยืม, หนังสือสัญญา) เป็นงานในหมวด "กลุ่มงานบริหาร" ที่ยังเป็น "เร็วๆ นี้" (ยังไม่มีทะเบียนบันทึกข้อมูลจริง) ต้องสร้างทะเบียนของงานเหล่านั้นก่อน จึงจะออกรายงานรูปแบบเดียวกันนี้ให้ได้
7. **ธีม**: ปรับโทนสีฟ้าทันสมัยขึ้น หัวเพจ (PageHeader) เป็นแถบฟ้าเข้มไล่สี หัวข้อเมนูงานหลัก (ทะเบียนหลัก, แผนงานและรายงาน) เป็นแถบสีตัวหนาใหญ่ในเมนูซ้าย แยกจากงานรองชัดเจน และเพิ่มอิโมจิสีสันประจำแต่ละงาน
8. **วันลารายบุคคล**: ในเมนู "ทะเบียนควบคุมวันลา" เพิ่มแท็บ "รายบุคคล" แสดงรายชื่อบุคลากรทั้งหมด (เห็นเฉพาะผู้อำนวยการ/ธุรการ/Super Admin) คลิกชื่อใครเพื่อดูแดชบอร์ดวันลาคงเหลือ/สถิติของคนนั้น พร้อมปุ่ม "ยื่นใบลา" เฉพาะบุคคล (ยื่นแทนผู้อื่นได้เฉพาะ Super Admin/ธุรการ ตามสิทธิ์เดิมของระบบ)

## เวอร์ชัน 5: ปรับรายงาน/ทะเบียนตามผลตอบรับ, ใบลา PDF ตามแบบฟอร์มจริง

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`)
2. **ปุ่มรายงาน**: แต่ละทะเบียนเหลือปุ่มส่งออกเพียงชุดเดียว คือ **CSV / Excel (ลายแถบสีทะเบียนราชการ) / PDF** (ตัดปุ่ม Excel แบบเรียบที่ซ้ำซ้อนออกแล้ว)
3. **ทะเบียนหนังสือส่ง**: ช่อง "ผู้รับผิดชอบ" เปลี่ยนเป็นดรอปดาวน์ดึงชื่อจากทำเนียบบุคลากรโดยอัตโนมัติ และช่องเลขที่แทรกย้อนหลังจะคำนวณ/แสดงเลขแทรกจริง (เช่น /20.1) ให้เห็นก่อนกดบันทึก แทนที่จะโชว์เป็นเครื่องหมาย "x" เหมือนก่อน
4. **ทะเบียนหนังสือรับ**: ตัดช่อง "กำหนดดำเนินการ" และ "วันที่ดำเนินการ" ออก, เมื่อกดบันทึกจะค้างหน้าต่างไว้ให้เห็นกล่อง "เลขรับ" และ "เวลาที่รับหนังสือ" ชัดเจนก่อนปิดเอง (ไฟล์แนบเก็บและค้นดูได้ตามเดิม เพราะระบบแนบไฟล์ใช้ร่วมกันทุกทะเบียนอยู่แล้ว)
5. **วันลารายบุคคล**: จัดเรียงรายชื่อตามลำดับตำแหน่ง (นักวิชาการสาธารณสุขชำนาญการพิเศษ → นักวิชาการสาธารณสุข → พยาบาลวิชาชีพ → แพทย์แผนไทย → ผู้ช่วยเหลือคนไข้ → พนักงานบริการ → พนักงานการเงินและบัญชี → คนขับรถ) ชื่อบุคลากรแสดงเด่นอยู่หน้าลิสต์เลย พร้อมแดชบอร์ดโควตาคงเหลือ/ใช้ไปแต่ละประเภทของแต่ละคน และปุ่ม "ยื่นใบลา" ท้ายแถวของแต่ละคน
6. **หัวข้อหน้าเพจ**: ปรับตัวหนังสือหัวข้อเป็นสีขาวทึบตัดกับแถบพื้นหลังสีฟ้าให้ชัดเจนขึ้น พร้อมอิโมจิกระพริบประจำแต่ละงาน
7. **ใบลา PDF ตามแบบฟอร์มจริง**: เพิ่มปุ่มพิมพ์ (ไอคอนเครื่องพิมพ์) ที่ท้ายแถวใบลาทุกใบ ทั้งในตารางรวมและในแดชบอร์ดรายบุคคล กดแล้วเปิดแท็บใหม่เป็นแบบฟอร์มใบลาให้ใช้ฟังก์ชัน "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์ โดยรูปแบบฟอร์มจะเปลี่ยนไปตามประเภทการลา:
   - ลาป่วย/ลากิจส่วนตัว/ลาคลอดบุตร → แบบฟอร์มรวม 3 ประเภท (มีช่องติ๊กประเภทที่เลือก) ตามตัวอย่างที่แนบ
   - ลาพักผ่อน → แบบใบลาพักผ่อน พร้อม "บันทึกข้อความ" หน้าที่สองสำหรับส่งเรื่องให้กองสาธารณสุขพิจารณา ตามตัวอย่างที่แนบ
   - ลาอุปสมบท/ประกอบพิธีฮัจย์ → แบบใบลาอุปสมบทตามตัวอย่าง (รายละเอียดเฉพาะทาง เช่น ชื่อวัด ให้กรอกด้วยลายมือในช่องเว้นว่าง เนื่องจากระบบยังไม่มีช่องเก็บข้อมูลเหล่านี้)
   - ประเภทลาอื่นๆ ที่ไม่มีตัวอย่างแนบมา (ลาไปช่วยเหลือภริยาคลอดบุตร/ลาไปศึกษาฝึกอบรม/อื่นๆ) → ใช้โครงร่างฟอร์มใกล้เคียงกันเป็นแบบมาตรฐานกลาง
   - หมายเหตุ: แบบฟอร์ม "ใบขอยกเลิกวันลา" ที่แนบมาเป็นตัวอย่างเพิ่มเติม ยังไม่ได้ทำเป็นหน้าพิมพ์แยกในรอบนี้ (ปัจจุบันการยกเลิกใบลาทำผ่านปุ่ม "ยกเลิก" ในตารางได้อยู่แล้ว แต่ยังไม่ออกเป็นเอกสาร PDF ตามแบบฟอร์ม)

## เวอร์ชัน 6: ปุ่มยกเลิกวันลาแบบเลือกช้อย (สิทธิ์เฉพาะ Super Admin), ใบลา PDF ตามแบบฟอร์มจริง 2 แผ่นทุกประเภท

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ **และรอบนี้ต้องนำ `firestore.rules` ไปเผยแพร่ใหม่ด้วย** (Firebase Console → Firestore Database → Rules หรือ `firebase deploy --only firestore:rules`) มิฉะนั้นสิทธิ์การยกเลิกวันลาจะยังเป็นแบบเดิม
2. **ปุ่ม "ยกเลิกวันลา" ในหัวทะเบียนควบคุมวันลา**: กดแล้วขึ้นหน้าต่างให้เลือกจากช้อยว่าจะยกเลิกใบลาใบไหน
   - **Super Admin** เท่านั้นที่เลือกยกเลิก/ลบถาวรแทนใครก็ได้ทุกใบ (รวมถึงใบที่อนุมัติ/ไม่อนุมัติไปแล้ว)
   - บุคคลอื่น (รวมถึงผู้อำนวยการ) เลือกยกเลิกได้เฉพาะใบลาของตัวเองที่ยังอยู่ในสถานะ "รอพิจารณา" เท่านั้น จะยกเลิกแทนคนอื่นไม่ได้
   - ปรับ `firestore.rules` ให้ Super Admin แก้/ยกเลิกแทนใครก็ได้ทุกกรณี, ผู้อำนวยการพิจารณาได้เฉพาะอนุมัติ/ไม่อนุมัติ (ยกเลิกแทนคนอื่นไม่ได้แม้เป็นผู้อำนวยการ), เจ้าของใบลายกเลิกได้เฉพาะใบตัวเองตอนยังรอพิจารณา ตรงกับสิทธิ์ที่ UI บังคับไว้
3. **ฟอร์มยื่นใบลา**: เพิ่มช่อง "มอบหมายงานในหน้าที่ให้" เป็นดรอปดาวน์ดึงรายชื่อจากทำเนียบบุคลากร (เลือกผู้รับมอบงานระหว่างลา) บันทึกไว้ในใบลาเพื่อพิมพ์ลงแบบฟอร์ม
4. **ใบลา PDF ปรับตามตัวอย่างที่แนบใหม่ทุกจุด**:
   - ตัดโลโก้ รพ.สต. ออกจากหัวแบบฟอร์มทุกใบ
   - เพิ่มส่วน "คำสั่ง...มอบหมายการทำงานในหน้าที่ให้...เป็นผู้ดำเนินการแทน" พร้อมช่องเซ็นชื่อ "ผู้มอบงาน" (ชื่อผู้ทำใบลา) และ "ผู้รับมอบงาน" (ชื่อที่เลือกจากช้อยข้อ 3) ต่อท้ายลายเซ็นผู้ยื่นใบลาในทุกแบบฟอร์ม
   - ช่อง "ผู้ตรวจสอบ" เซ็นชื่อ-ตำแหน่งไว้ล่วงหน้าเป็น "นางสาวพิไลวรรณ กุลมินทร์ / นักวิชาการสาธารณสุขชำนาญการ" พร้อมวันที่เติมให้อัตโนมัติตามวันที่เริ่มลาของใบนั้น (ไม่ต้องกรอกเอง)
   - ช่อง "ความเห็นของผู้บังคับบัญชา" เซ็นชื่อ-ตำแหน่งไว้ล่วงหน้าเป็นบุคคลเดียวกันเช่นกัน
   - ช่อง "เรียน" คำนวณอัตโนมัติ: ใบลาของนายพงศกร แป่มจำนัก (ผู้อำนวยการ) → "เรียน ผู้อำนวยการกองสาธารณสุข", ใบลาของพนักงานคนอื่นทุกคน → "เรียน ผู้อำนวยการโรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม" ใช้ทั้งหน้าใบลาและหน้าบันทึกข้อความ
   - ตัดข้อความท้ายกระดาษ "พิมพ์จากระบบ NSN-PHC Management System เมื่อวันที่..." ออกทั้งหมด
   - **การลาทุกประเภท** (ไม่ใช่แค่ลาพักผ่อนเหมือนเวอร์ชันก่อน) ส่งออกเป็น PDF 2 แผ่นเสมอ: แผ่นที่ 1 = ใบลา, แผ่นที่ 2 = "บันทึกข้อความ" ขอส่งใบลาเพื่อพิจารณา จ่าหน้าตาม "เรียน" ข้างต้น และลงชื่อท้ายบันทึกด้วยชื่อผู้ขอลาเอง (ไม่ใช่ชื่อผู้บริหาร)

## เวอร์ชัน 7: ใบลา PDF ตรงตามแบบฟอร์มจริงที่แนบ (แผ่นเดียว), ยกยอดวันลาพักผ่อน, ที่วาง TOKEN แจ้งเตือนไลน์

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ **และรอบนี้ต้องนำ `firestore.rules` ไปเผยแพร่ใหม่อีกครั้ง** (มีการแก้เรื่องสิทธิ์อ่าน TOKEN ไลน์)
2. **ใบลา PDF ปรับให้ตรงกับแบบฟอร์มตัวอย่างจริงที่แนบมาเป๊ะๆ และพอดี 1 หน้าเท่านั้น** (ตัดหน้า "บันทึกข้อความ" แผ่นที่ 2 ออกตามที่แจ้ง ไม่ต้องการแล้ว):
   - ตัดวันที่/เวลาที่ระบบเคยเติมให้อัตโนมัติออกทั้งหมด (ช่อง "วันที่" หัวกระดาษ และวันที่ในช่องผู้ตรวจสอบ/ผู้บังคับบัญชา/คำสั่ง) เหลือเป็นช่องเว้นว่างให้กรอกด้วยลายมือทุกจุด ตรงตามแบบฟอร์มตัวอย่าง
   - ซ่อนชื่อโปรแกรมออกจากหัว/ท้ายกระดาษที่เบราว์เซอร์แทรกให้อัตโนมัติตอนพิมพ์ พร้อมมีข้อความแนะนำในหน้าพิมพ์ให้ปิดตัวเลือก "ส่วนหัวและส่วนท้าย" (Headers and footers) ในกล่องตั้งค่าพิมพ์ของเบราว์เซอร์ เพื่อไม่ให้มีวันที่/URL แทรกเข้ามาอีกชั้น (จุดนี้เบราว์เซอร์เป็นผู้ควบคุม เว็บปิดให้อัตโนมัติทั้งหมดไม่ได้)
   - แบบใบลาป่วย/ลากิจส่วนตัว/ลาคลอดบุตร: ปรับกลับให้ตรงตามแบบฟอร์มตัวอย่าง (ไม่มีส่วนมอบหมายงาน/ไม่มีชื่อผู้ตรวจสอบพิมพ์ไว้ล่วงหน้า เว้นว่างให้เซ็นด้วยลายมือทั้งหมด) พร้อมเติมเครื่องหมาย ✓ ลงในช่องสี่เหลี่ยมของประเภทที่ขอลาให้ตรงช่องอัตโนมัติ
   - แบบใบลาพักผ่อน: ตรงตามแบบฟอร์มตัวอย่าง มีช่อง "คำสั่งมอบหมายงาน" (ผู้มอบงาน/ผู้รับมอบงาน) และเซ็นชื่อ-ตำแหน่งไว้ล่วงหน้า คือ "ผู้ตรวจสอบ: นางสาวพิไลวรรณ กุลมินทร์" และ "ความเห็นของผู้บังคับบัญชา: นายพงศกร แป่มจำนัก" (ยกเว้นเป็นใบลาของนายพงศกรเอง จะเว้นว่างช่องนี้ไว้ เพราะไม่มีผู้บังคับบัญชาที่ระบุตายตัวได้)
   - เพิ่มช่อง "หมายเลขโทรศัพท์มือถือ" แยกจากช่อง "ติดต่อได้ที่" ในฟอร์มยื่นใบลา ให้ตรงกับที่แบบฟอร์มตัวอย่างต้องการ
   - ยอดวันลาพักผ่อนสะสม (ยกยอดเก่า) และสิทธิ์คงเหลือปีนี้ คำนวณจากข้อมูลจริงเติมลงในแบบฟอร์มให้อัตโนมัติ (ดูข้อ 3)
3. **ยกยอดวันลาพักผ่อนสะสม**: เพิ่มช่องกรอกตัวเลข "ยกยอดลาพักผ่อนสะสม" ต่อคนที่หน้า "ทำเนียบบุคลากร" (แก้ได้เฉพาะ Super Admin) ใช้เป็นค่าตั้งต้นสำหรับคำนวณ "มีวันลาพักผ่อนสะสม" ในแบบใบลาพักผ่อนของแต่ละคน
4. **ที่วาง TOKEN สำหรับแจ้งเตือนไลน์กลุ่ม (LINE Notify)**: เพิ่มส่วนตั้งค่าใหม่ที่หน้า "ตั้งค่าระบบ" (Super Admin เท่านั้น)
   - มีช่องให้วาง TOKEN จาก [notify-bot.line.me/my](https://notify-bot.line.me/my/) (สร้าง Token แล้วเลือกกลุ่มไลน์ปลายทางได้เลย) พร้อมสวิตช์เปิด/ปิด และเลือกได้ว่าจะแจ้งเตือนตอนไหนบ้าง (ยื่นใบลาใหม่ / อนุมัติ-ไม่อนุมัติ / ยกเลิก)
   - **เพื่อความปลอดภัย TOKEN ที่บันทึกไปแล้วจะดึงกลับมาดูไม่ได้อีกเลย แม้แต่ Super Admin** (เขียนได้ทางเดียว) ป้องกันไม่ให้หลุดไปถึงผู้ใช้อื่นในระบบ
   - **สำคัญ**: การตั้งค่านี้เป็นแค่ "ที่เก็บ TOKEN" เท่านั้น ตัวส่งข้อความจริงต้องติดตั้ง Cloud Function เสริม 1 ตัว (เตรียมโค้ดพร้อมใช้ไว้ในโฟลเดอร์ `functions/` ในซิปนี้แล้ว) เพราะ LINE Notify ไม่ยอมให้เว็บเบราว์เซอร์เรียก API ตรงๆ (ติดปัญหา CORS) ต้องมีตัวกลางฝั่งเซิร์ฟเวอร์ — ขั้นตอนติดตั้งเพิ่มเติม (ทำครั้งเดียว ไม่บ่อย):
     1. ไปที่ Firebase Console → โปรเจกต์ `nsn-phc-web` → เมนู Upgrade เป็นแพ็กเกจ **Blaze** (จ่ายตามใช้จริง แต่ปริมาณแจ้งเตือนของหน่วยงานเล็กระดับนี้ไม่น่าจะมีค่าใช้จ่ายเกินโควตาฟรี)
     2. ติดตั้ง Firebase CLI บนเครื่องที่มีโฟลเดอร์โปรเจกต์นี้: `npm install -g firebase-tools` แล้ว `firebase login`
     3. ที่โฟลเดอร์โปรเจกต์ (มีไฟล์ `firebase.json`, `.firebaserc`, `functions/` ให้พร้อมแล้ว) รันคำสั่ง `firebase deploy --only functions`
     4. เข้าหน้า "ตั้งค่าระบบ" ในเว็บ วาง TOKEN ไลน์ เปิดสวิตช์ใช้งาน แล้วลองยื่นใบลาทดสอบ 1 ใบ ข้อความควรเด้งเข้ากลุ่มไลน์ภายในไม่กี่วินาที

## เวอร์ชัน 8: ใบลา PDF เติมวันที่/ผู้ตรวจสอบ/คำสั่งอนุญาตให้อัตโนมัติ, ฟอนต์ TH SarabunIT๙

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`)
2. **ใบลา PDF ทุกประเภท** ปรับให้เติมข้อมูลอัตโนมัติเพิ่มตามที่แจ้ง (ใบลาป่วย/กิจ/คลอด, ลาพักผ่อน, อุปสมบท, ลาประเภทอื่นๆ ทุกแบบเหมือนกันหมด):
   - ช่อง **"วันที่"** หัวกระดาษ เติมอัตโนมัติเป็นวันที่บันทึกใบลาเข้าระบบจริง (ไม่ใช่วันที่เริ่มลา)
   - ช่อง **"ผู้ตรวจสอบ"** และ **"ความเห็นของผู้บังคับบัญชา"** พิมพ์ชื่อ-ตำแหน่งไว้ล่วงหน้าเป็น "นางสาวพิไลวรรณ กุลมินทร์ / นักวิชาการสาธารณสุขชำนาญการ" ทั้งสองช่อง ทุกประเภทการลา (ก่อนหน้านี้บางแบบฟอร์มยังเว้นว่างอยู่)
   - กล่อง **"คำสั่ง" อนุญาต/ไม่อนุญาต** ติ๊กเครื่องหมายถูกในช่องสี่เหลี่ยมให้อัตโนมัติตามผลพิจารณาจริง (อนุมัติ/ไม่อนุมัติ) และลงชื่อผู้อนุญาตไว้ล่วงหน้าเป็น "นายพงศกร แป่มจำนัก / ผู้อำนวยการโรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม" พร้อมวันที่เติมอัตโนมัติตามวันที่กดบันทึกผลพิจารณาจริง — ยกเว้นเป็นใบลาของนายพงศกรเอง จะเว้นช่องนี้ว่างไว้ให้เซ็นเอง (เพราะไม่มีใครลงนามแทนตายตัวได้)
   - ช่อง "สถิติการลาในปีงบประมาณนี้" ยังคงดึงข้อมูลวันลาแต่ละประเภทที่เคยบันทึกไว้จริงมาเติมให้อัตโนมัติเหมือนเดิม
3. **ฟอนต์แบบฟอร์ม PDF** เปลี่ยนมาใช้ฟอนต์ **TH SarabunIT๙** ทั้งฉบับ ตามที่ต้องการ — ข้อควรทราบ: ฟอนต์นี้ต้องติดตั้งไว้ในเครื่องคอมพิวเตอร์ที่ใช้เปิด/พิมพ์หน้านี้ก่อน (เป็นฟอนต์ที่นิยมติดตั้งไว้ในเครื่องราชการอยู่แล้ว) หากเครื่องไหนไม่มีฟอนต์นี้ เว็บจะเปลี่ยนไปแสดงผลด้วยฟอนต์ใกล้เคียง (Sarabun) แทนโดยอัตโนมัติ ไม่ทำให้หน้าเพี้ยนหรือพัง

## เวอร์ชัน 9: ฝังฟอนต์ TH SarabunIT๙ ในไฟล์ (ไม่ต้องติดตั้งเอง), ขนาด/ตัวหนา/ระยะขอบตามหนังสือราชการ

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`) — **ไฟล์ฟอนต์ 3 ไฟล์ที่แนบมาได้ถูกฝังไว้ในโค้ดให้แล้ว** ไม่ต้องติดตั้งฟอนต์ในเครื่องเพิ่มเติมอีก
2. **ฝังฟอนต์ TH SarabunIT๙ ลงในไฟล์ที่ส่งออกโดยตรง**: ใบลา PDF ทุกประเภทตอนนี้แสดงผลด้วยฟอนต์นี้เสมอ ไม่ว่าเครื่องที่เปิด/พิมพ์จะติดตั้งฟอนต์นี้ไว้หรือไม่ก็ตาม (ฝังไฟล์ฟอนต์ไปกับหน้าเว็บเลย ไม่ต้องพึ่งฟอนต์ในเครื่อง) — หมายเหตุ: ไฟล์ที่แนบมามีเฉพาะตัวปกติ/ตัวเอียง/ตัวหนา-เอียง ไม่มีไฟล์ตัวหนาตรงแยกให้ ระบบจึงให้เบราว์เซอร์สังเคราะห์ตัวหนาจากตัวปกติแทนในจุดที่ต้องการตัวหนา (ผลลัพธ์ยังคงชัดเจนอ่านง่ายตามปกติ)
3. **ขนาด/น้ำหนักตัวอักษร**: กำหนดขนาดตัวอักษรพื้นฐานเป็น 16 ตัวธรรมดาทั้งฉบับ ส่วนหัวข้อ (ชื่อแบบฟอร์ม, "ความเห็นของผู้บังคับบัญชา", "คำสั่ง", "สถิติการลาในปีงบประมาณนี้") และคำว่า "(ลงชื่อ)" ทุกจุด กำหนดเป็นตัวหนา
4. **ระยะขอบกระดาษ**: กำหนดขนาดกระดาษ A4 พร้อมระยะขอบตามมาตรฐานหนังสือราชการ (บน 2.5 ซม., ซ้าย 3 ซม. เผื่อเข้าเล่ม, ขวา/ล่าง 2 ซม.) ให้เบราว์เซอร์จัดหน้าตามนี้ตอนพิมพ์/บันทึกเป็น PDF โดยอัตโนมัติ

## เวอร์ชัน 10: ปรับเส้น/ระยะห่าง/การจัดวางในใบลา PDF ให้สวยงามตรงตามตัวอย่าง

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`)
2. **วันที่หัวกระดาษ**: ย้ายคำว่า "วันที่ ..." จากชิดขวา มาอยู่กึ่งกลางหน้ากระดาษพอดี
3. **ลายเซ็นผู้ยื่นใบลา**: ปรับเส้นประให้อยู่กึ่งกลางและมีความยาวพอดีกับชื่อ-ตำแหน่งด้านล่าง ดูสวยงามเป็นระเบียบขึ้น (ทุกแบบฟอร์ม)
4. **"ความเห็นของผู้บังคับบัญชา"**: เว้นระยะห่างก่อนถึงชื่อมากขึ้น เพิ่มบรรทัด "หัวหน้างานบริหาร" ต่อท้ายใต้ตำแหน่ง "นักวิชาการสาธารณสุขชำนาญการ" ของนางสาวพิไลวรรณ กุลมินทร์
5. **"ผู้ตรวจสอบ"**: จัดชื่อ-ตำแหน่ง-เส้นประทั้งหมดให้อยู่กึ่งกลาง แทนการชิดซ้ายแบบเดิม
6. **ผู้มอบงาน/ผู้รับมอบงาน ระหว่างลา**: เพิ่มจุดลงชื่อพร้อมชื่อผู้ยื่นใบลา (ผู้มอบงาน) และชื่อผู้ที่เลือกไว้ในฟอร์ม (ผู้รับมอบงาน) ไว้ใต้ตารางสถิติการลา ครบทุกประเภทใบลา (ก่อนหน้านี้มีเฉพาะแบบใบลาพักผ่อน)
7. **กล่อง "คำสั่ง" อนุญาต/ไม่อนุญาต**: ย้ายมาจัดวางในแนวเดียวกับ "ความเห็นของผู้บังคับบัญชา" (คอลัมน์ขวาเดียวกัน เรียงต่อกันลงมา) ปรับเส้นประสำหรับลงความเห็นให้เท่ากับด้านบน เพิ่มเส้นประสำหรับให้นายพงศกร แป่มจำนัก เซ็นชื่อให้พอดีกับชื่อ-ตำแหน่ง พร้อมเว้นระยะห่างจากเส้นประลงความเห็นด้านบนให้พอเหมาะสวยงาม
8. **ระยะขอบกระดาษ**: ปรับเป็นหัวกระดาษและท้ายกระดาษ 2.5 ซม. ซ้าย-ขวา 2 ซม. เท่ากันทั้งสองด้าน (ตัดระยะเผื่อเข้าเล่มด้านซ้ายที่เคยเป็น 3 ซม. ออก ตามที่แจ้งล่าสุด)

## เวอร์ชัน 11: ปรับที่อยู่หน่วยงาน, ระยะขอบ 2.5 ซม.รอบด้าน, เส้นประลงชื่อให้กระชับสวยงามขึ้นอีก

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`)
2. **ที่อยู่หน่วยงานหัวกระดาษ**: ปรับข้อความเป็น "โรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม ตำบลเชียงเครือ อำเภอเมืองสกลนคร จังหวัดสกลนคร 47000" และเปลี่ยนการจัดวางจากชิดขวา เป็นชิดซ้าย เพื่อให้หากตัวอักษรยาวจนต้องขึ้นบรรทัดที่ 2 จะขึ้นต้นตรงกับอักษรตัวแรกของบรรทัดบนพอดี
3. **ระยะขอบกระดาษ**: ปรับเป็น 2.5 ซม. เท่ากันทั้ง 4 ด้าน (บน-ล่าง-ซ้าย-ขวา) ทำให้ "เรื่อง" "เรียน" และเนื้อความทุกบรรทัดห่างจากขอบกระดาษ 2.5 ซม.ตรงกันทุกด้าน
4. **เส้นประลงชื่อผู้ยื่นใบลา**: ลดระยะห่างระหว่างเส้นประกับชื่อในวงเล็บด้านล่างให้กระชับพอดีขึ้น (ทุกแบบฟอร์ม)
5. **ช่องมอบหมายงานระหว่างลา** (ผู้มอบงาน/ผู้รับมอบงาน): ตัดคำว่า "คำสั่ง" ที่ซ้ำกับกล่องอนุญาต/ไม่อนุญาตออก และจัดชื่อผู้มอบงาน/ผู้รับมอบงานให้อยู่กึ่งกลางใต้เส้นประแต่ละเส้น
6. **ความเห็นของผู้บังคับบัญชา**: เพิ่มเส้นประให้นางสาวพิไลวรรณ กุลมินทร์ เซ็นชื่อพอดีกับวงเล็บชื่อ และดึงบรรทัดตำแหน่ง "นักวิชาการสาธารณสุขชำนาญการ" กับ "หัวหน้างานบริหาร" ให้ชิดใกล้ชื่อมากขึ้น (ไม่เว้นห่างเกินไปเหมือนเดิม)
7. **บันทึกไฟล์ PDF ไปที่ Downloads อัตโนมัติ**: การกำหนดปลายทางบันทึกไฟล์เป็นสิทธิ์ของเบราว์เซอร์/ระบบปฏิบัติการ ไม่ใช่สิ่งที่เว็บไซต์กำหนดเองได้ (เพื่อความปลอดภัยของผู้ใช้ เบราว์เซอร์ทุกยี่ห้อไม่อนุญาตให้เว็บสั่งบันทึกไฟล์ไปที่ไหนก็ได้โดยไม่ถามผู้ใช้) วิธีทำให้บันทึกไป Downloads อัตโนมัติทุกครั้งโดยไม่ต้องเลือกที่เก็บเอง: เปิดการตั้งค่าเบราว์เซอร์ (เช่น Chrome: การตั้งค่า → ดาวน์โหลด) แล้ว **ปิด** ตัวเลือก "ถามก่อนว่าจะบันทึกไฟล์แต่ละไฟล์ไว้ที่ไหน" — เพิ่มคำแนะนำนี้ไว้ในข้อความเคล็ดลับที่หน้าพิมพ์ใบลาให้แล้ว

## เวอร์ชัน 12: เลขหนังสือส่งช่องเดียว/ปีงบประมาณ 2569, เปิดสิทธิ์แก้ไข/ลบหนังสือรับ-ส่งได้ทุกคน, แก้บั๊กสำรองข้อมูล, ระบบจัดการ Username/Password โดย Super Admin, ปรับใบลา PDF เพิ่มเติม

**⚠️ ต้องอัปเดต Firestore Rules ด้วย (สำคัญ)**: รอบนี้มีการแก้ไข `firestore.rules` หลายจุด (เปิดสิทธิ์หนังสือรับ/ส่ง, เพิ่มคอลเลกชันใหม่ `credentials` และ `accountChangeRequests`) — หลังอัปโหลดไฟล์เว็บแล้ว ต้องคัดลอกเนื้อหาไฟล์ `firestore.rules` ทั้งหมดไปวางที่ Firebase Console → Firestore Database → Rules → กด Publish ด้วย มิฉะนั้นฟีเจอร์ใหม่รอบนี้จะใช้งานไม่ได้

1. **ทะเบียนหนังสือส่ง — เลขที่รันอัตโนมัติช่องเดียว**: ตัดช่องกรอกเลขที่หนังสือด้วยมือ (ที่ซ้ำซ้อน) ออก เหลือเฉพาะเลขที่ที่ระบบรันให้อัตโนมัติ (เช่น สน 51006.24/25) ปุ่ม "แทรกเลขที่ย้อนหลัง" (กรณีมีหนังสือเก่าที่ยังไม่เคยลงเลขในระบบ) ยังใช้งานได้ตามเดิมในหน้าทะเบียนหนังสือส่ง
2. **ปีงบประมาณเริ่มนับใหม่**: แก้ปีงบประมาณเริ่มต้นที่ระบบเปิดให้เลือกจาก 2570 กลับมาเป็น **2569** ตามปีงบประมาณปัจจุบันจริง (แก้บั๊กที่ทำให้บันทึกหนังสือวันที่ปัจจุบันไม่ได้)
3. **แก้ไข/ลบหนังสือรับ-หนังสือส่งได้ทุกคน**: เดิมจำกัดเฉพาะ Super Admin/ธุรการ ตอนนี้ผู้ใช้งานทุกคนที่ยังไม่ถูกระงับสิทธิ์ สามารถกดแก้ไขหรือลบทะเบียนหนังสือรับ/ส่งได้ (ปรับทั้งฝั่งเว็บและ `firestore.rules`)
4. **แก้บั๊กสำรองข้อมูล (ส่งออกไม่สำเร็จ)**: ปรับวิธีดาวน์โหลดไฟล์สำรองข้อมูลให้เปิดแท็บสำรองไว้ตั้งแต่จังหวะกดปุ่ม (ก่อนรอข้อมูลจาก Firestore) เผื่อกรณีเบราว์เซอร์บางตัวบล็อกการดาวน์โหลดอัตโนมัติที่มีช่วงรอคั่นกลาง — **หากลองใหม่แล้วยังส่งออกไม่สำเร็จอีก กรุณาแจ้งข้อความ error สีแดงที่ขึ้นตอนกดส่งออกให้ทราบด้วย** เพื่อตรวจสอบสาเหตุที่แท้จริงต่อไป (ไม่สามารถจำลองปัญหาเดียวกันได้จากฝั่งนี้)
5. **ระบบจัดการผู้ใช้งานสำหรับ Super Admin** (หน้า "ทำเนียบบุคลากร"):
   - กำหนด Username/Password ให้ผู้ใช้งานแต่ละคนไว้ล่วงหน้าแล้ว และเพิ่มคอลัมน์แสดงรหัสผ่าน (กดปุ่มดูได้) ให้ Super Admin เห็น เพื่อนำไปแจ้งเจ้าของบัญชี
   - ปุ่ม **แก้ไขข้อมูลส่วนตัว**: แก้ชื่อ-สกุล ตำแหน่ง รวมถึงเปลี่ยน Username/Password ของผู้ใช้งานแต่ละคนได้จากหน้านี้เลย
   - ปุ่ม **ลบผู้ใช้งานออกจากระบบถาวร**: ลบสิทธิ์การเข้าใช้งานออกจากระบบทันที (มีกล่องยืนยันก่อนลบ)
   - หน้าล็อกอิน เพิ่มลิงก์ **"ขอแก้ไข Username/Password"** ให้ผู้ใช้งานที่ต้องการเปลี่ยนเอง ส่งคำขอมาให้ Super Admin พิจารณาอนุมัติ (แสดงรายการคำขอที่หน้าทำเนียบบุคลากร)
   - **ข้อจำกัดของ Firebase ที่ควรทราบ**: ระบบยืนยันตัวตน (Firebase Authentication) ไม่อนุญาตให้อ่านรหัสผ่านจริงกลับออกมาได้ไม่ว่ากรณีใด — รหัสผ่านที่ Super Admin เห็นในหน้านี้เป็น "สำเนา" ที่ระบบเก็บแยกไว้ต่างหาก (คอลเลกชัน `credentials` เข้าถึงได้เฉพาะ Super Admin) ไม่ใช่ค่าจริงจากระบบยืนยันตัวตน และบางกรณี (เช่น เปลี่ยนรหัสผ่านให้บัญชีที่มีอยู่แล้ว) ต้องเข้าไปลบบัญชีเดิมที่ Firebase Console ก่อนระบบจึงจะสร้างบัญชีใหม่ให้ได้ครบสมบูรณ์ — เป็นข้อจำกัดของ Firebase เอง ไม่ใช่บั๊กของระบบ
   - ไฟล์สำรองข้อมูลตอนนี้รวมสำเนารหัสผ่าน (`credentials`) ไว้ด้วยแล้ว (ปรับข้อความอธิบายที่หน้าสำรองข้อมูลให้ตรงกับความจริง)
6. **ใบลา PDF ปรับเพิ่มเติม**:
   - ที่อยู่หน่วยงานที่หัวกระดาษ ปรับกลับมาชิดมุมกระดาษด้านขวาตามระเบียบงานสารบรรณ (บรรทัดที่ 2 ยังคงขึ้นต้นตรงกับตัวอักษรแรกของบรรทัดบน "โ" เหมือนเดิม)
   - วันที่ใต้ลายเซ็น "ผู้ตรวจสอบ" และ "ความเห็นของผู้บังคับบัญชา" ตัดรูปแบบ วัน/เดือน/พ.ศ. ออก เหลือเพียง "วันที่..........." บรรทัดเดียว และขยับให้ชิดใต้ตำแหน่งมากขึ้น
   - ลดระยะห่างระหว่างชื่อกับบรรทัดตำแหน่ง (นักวิชาการสาธารณสุขชำนาญการ / หัวหน้างานบริหาร / ผู้อำนวยการฯ) ให้ชิดกันมากขึ้นอีกทั้งฝั่งผู้ตรวจสอบ ความเห็นผู้บังคับบัญชา และคำสั่งอนุญาต

## เวอร์ชัน 13: ตัดช่องที่ไม่จำเป็นในหนังสือรับ/ส่ง, เลขรับ+วันที่+เวลาออกอัตโนมัติจริง, เตรียมระบบแจ้งเตือนไลน์ใหม่ (LINE Messaging API)

1. **ทะเบียนหนังสือส่ง**: ตัดช่อง "กลุ่มงาน" และ "สถานะ" ออก (ไม่ใช้แล้ว) ส่วนช่อง "ถึง" ยังคงเลือกจากรายชื่อหน่วยงาน/บุคคลที่ใช้บ่อยได้เหมือนเดิม และถ้าเลือก **"อื่นๆ (ระบุ)"** ที่ไม่มีในช้อย ระบบจะเปิดช่องให้พิมพ์เองขึ้นมาอัตโนมัติทันที (ฟีเจอร์นี้มีอยู่แล้ว ยืนยันว่าทำงานถูกต้อง)
2. **ทะเบียนหนังสือรับ**:
   - ตัดช่อง "ผู้รับผิดชอบ" และ "กลุ่มงาน" ออก
   - ช่อง "ถึง" เปลี่ยนเป็นเลือกจากรายชื่อบุคลากร ตั้งค่าเริ่มต้นเป็น **"ผู้อำนวยการโรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม"** ให้อัตโนมัติ ถ้าเป็นถึงบุคลากรท่านอื่นก็คลิกเลือกเปลี่ยนได้จากช้อยเดียวกัน
   - **เลขรับ + วันที่ + เวลารับ ออกให้อัตโนมัติจริงตามเวลาที่กดบันทึก แก้ไขเองไม่ได้อีกต่อไป** (แก้ปัญหาที่ตัวเลข/วันที่/เวลาที่ระบบโชว์ไว้ตอนแรกไม่ตรงกับค่าที่บันทึกจริง) หน้าฟอร์มจะโชว์เลขรับ+วันที่+เวลาที่ "กำลังจะออกให้" ล่วงหน้าเป็นตัวอย่างก่อนกดบันทึกด้วย
   - หลังบันทึกสำเร็จ เพิ่มปุ่ม **"แนบไฟล์เอกสาร"** ในหน้าต่างยืนยัน กดแล้วเข้าไปแนบไฟล์หนังสือรับ (PDF/รูปสแกน) เก็บเข้าฐานข้อมูลได้ทันที (ระบบแนบไฟล์นี้มีอยู่แล้วในทุกทะเบียน ปรับให้เข้าถึงง่ายขึ้นสำหรับหนังสือรับโดยเฉพาะ)
   - แดชบอร์ดหน้าแรก การ์ด "หนังสือรับตามกลุ่มงาน" เปลี่ยนเป็น **"หนังสือรับตามความเร่งด่วน"** แทน เนื่องจากตัดช่องกลุ่มงานออกแล้ว
3. **แจ้งเตือนไลน์เมื่อมีการยื่น/อนุมัติวันลา — เปลี่ยนมาใช้ LINE Messaging API**:
   - ⚠️ **LINE ปิดบริการ "LINE Notify" ถาวรแล้วตั้งแต่ 31 มี.ค. 2568** ระบบเดิมที่วางไว้ตั้งแต่เวอร์ชัน 7 (ใช้ TOKEN จาก notify-bot.line.me) จึงใช้งานไม่ได้แล้วไม่ว่ากรณีใด ต้องเปลี่ยนวิธีใหม่ทั้งหมดตามนี้
   - ปรับหน้า "ตั้งค่าระบบ" ให้มี 2 ช่องแทนช่อง TOKEN เดิม: **Channel access token** และ **Target ID** (รหัสกลุ่ม/ผู้ใช้ปลายทางที่จะส่งข้อความเข้าไป) ทั้งสองช่องเขียนได้ทางเดียว ดูกลับไม่ได้แม้แต่ Super Admin (กันรั่วไหล) เหมือนระบบเดิม
   - ปรับ Cloud Function ในโฟลเดอร์ `functions/` ให้ยิงข้อความผ่าน LINE Messaging API (`https://api.line.me/v2/bot/message/push`) แทน — เมื่อมีการยื่นใบลาใหม่ หรือผู้อำนวยการกดอนุมัติ/ไม่อนุมัติ/ยกเลิก จะส่ง **ชื่อ-สกุลผู้ลา ประเภทการลา และวันที่ลา** เข้ากลุ่มไลน์ที่ตั้งไว้โดยอัตโนมัติ ตามที่ต้องการเป๊ะ
   - **ขั้นตอนเตรียมฝั่ง LINE ที่คุณต้องทำเอง** (ระบบเว็บทำแทนไม่ได้ เพราะต้องยืนยันตัวตนเจ้าของบัญชีไลน์):
     1. สมัคร **LINE Official Account** ฟรีที่ [LINE Official Account Manager](https://www.linebiz.com/th/service/line-official-account/) (ถ้ายังไม่มี)
     2. เปิดใช้งาน **Messaging API** ให้บัญชีนี้ที่ [LINE Developers Console](https://developers.line.biz/console/) แล้วสร้าง **Channel access token (long-lived)** — คัดลอกมาวางที่หน้า "ตั้งค่าระบบ" ของเว็บ
     3. เชิญบัญชี Official Account นี้เข้ากลุ่มไลน์ที่จะรับการแจ้งเตือน (หรือจะส่งหาบุคคลเดียวก็ได้)
     4. หา **Target ID** ของกลุ่ม/บุคคลนั้น (LINE ไม่มีหน้าจอโชว์ให้ดูตรงๆ ต้องอ่านจาก Webhook ที่ยิงเข้ามาตอนมีคนพิมพ์ข้อความในกลุ่มที่มีบอทอยู่) — **แจ้งให้ผู้พัฒนาช่วยตั้งค่าส่วนนี้ได้เมื่อสมัคร Official Account และเปิด Messaging API เสร็จแล้ว (ขั้นตอน 1-3)**
     5. ที่โฟลเดอร์โปรเจกต์ รันคำสั่ง `firebase deploy --only functions` อีกครั้งเพื่ออัปเดต Cloud Function เป็นเวอร์ชันใหม่ (ถ้าเคย deploy ไว้ก่อนหน้านี้)
     6. กลับมาหน้า "ตั้งค่าระบบ" วาง Channel access token + Target ID เปิดสวิตช์ใช้งาน แล้วลองยื่นใบลาทดสอบ 1 ใบ
   - **แนวคิดเพิ่มเติมที่แนะนำ** นอกเหนือจากที่วางแผนไว้ ลองพิจารณาดูว่าต้องการหรือไม่:
     - แจ้งเตือนแยก 2 กลุ่ม เช่น กลุ่มเจ้าหน้าที่ทั่วไป (แจ้งตอนยื่นใบลา) และกลุ่มผู้บริหาร (แจ้งเฉพาะตอนรออนุมัติ) — ทำได้โดยเพิ่ม Target ID ที่ 2 ในอนาคตหากต้องการ
     - แจ้งเตือนเมื่อ "หนังสือรับ" ใกล้ครบกำหนดดำเนินการ (จากช่อง "กำหนดดำเนินการ" ที่มีอยู่แล้ว) ไม่ใช่แค่เรื่องวันลา
     - แจ้งเตือนสรุปประจำวัน/สัปดาห์ (เช่น มีกี่ใบลารออนุมัติค้างอยู่) แทนที่จะแจ้งทีละรายการ
     - หากในอนาคตกลุ่มไลน์มีคนนอกหน่วยงานอยู่ด้วย ควรพิจารณาว่าจะแจ้งเฉพาะชื่อ-ประเภท-วันที่ตามที่วางแผนไว้พอ หรือจะเพิ่ม/ลดรายละเอียดในข้อความ (เช่น ไม่ใส่เหตุผลการลา เพื่อความเป็นส่วนตัวของผู้ลา)

## เวอร์ชัน 14: ปรับตัวเลือก "วิธีส่ง"/"สถานะ" เพิ่มเติม, ตัดช่องเลขที่หนังสือ/ลงวันที่ในหนังสือรับ

1. **หนังสือส่ง — ช่อง "ถึง" เลือก "อื่นๆ (ระบุ)"**: ตรวจสอบแล้วว่าระบบมีช่องพิมพ์เองโผล่ขึ้นมาอัตโนมัติทันทีใต้ช่อง "ถึง" อยู่แล้วตั้งแต่เดิม (ไม่ต้องเพิ่มโค้ดใหม่) — เลือก "อื่นๆ (ระบุ)" ในช้อยเมื่อไร จะมีช่องว่างเปล่าๆ ให้พิมพ์ชื่อผู้รับเองทันที
2. **หนังสือส่ง — เพิ่มตัวเลือกใน "วิธีส่ง"**: เพิ่ม **"แจ้งเวียนภายใน รพ.สต."** และ **"แจ้งเวียนโดย จนท.การเงินและบัญชี"** เข้าไปในช้อยวิธีส่ง (อยู่ก่อน "อื่น ๆ")
3. **หนังสือรับ — ตัดช่อง "เลขที่หนังสือ" และ "ลงวันที่" ออก**: เนื่องจากระบบออกเลขรับ/วันที่รับ/เวลารับให้อัตโนมัติอยู่แล้ว จึงตัดช่องกรอกเลขที่/วันที่ของหนังสือต้นฉบับที่เคยให้พิมพ์เองออกทั้งคู่ตามคำขอ (ยืนยันกับผู้ใช้แล้วว่าต้องการตัดทั้งสองช่อง)
4. **หนังสือรับ — เพิ่มตัวเลือกใน "สถานะ"**: เพิ่ม **"ส่งให้ ผอ.รพ.สต.พิจารณามอบหมาย"** เป็นสถานะใหม่ (อยู่ระหว่าง "กำลังดำเนินการ" กับ "ดำเนินการแล้ว")

## เวอร์ชัน 15: ปุ่ม "+" สำหรับกรอกเอง, ช้อย "ถึง" ในหนังสือรับตั้งผู้อำนวยการเป็นค่าเริ่มต้น, จัดวางเลขรับ/วันที่/เวลาให้ดูง่ายขึ้น

1. **หนังสือส่ง — ช่อง "ถึง" เลือก "อื่นๆ"**: เปลี่ยนจากที่ช่องพิมพ์เองโผล่ขึ้นมาทันที เป็น **กดปุ่ม "+ เพิ่มช่องพิมพ์เอง" ก่อน** ช่องกรอกจึงจะปรากฏขึ้นมาให้พิมพ์ (ตามที่ขอ)
2. **หนังสือรับ — ช่อง "ถึง"**: เพิ่มช้อย **"ผู้อำนวยการโรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม"** เป็นตัวเลือกตรึงไว้บนสุดของช้อยเสมอ และตั้งเป็น **ค่าเริ่มต้นในช่องทันทีที่เปิดฟอร์ม** ถ้าจะส่งถึงบุคลากรท่านอื่น คลิกเปลี่ยนเลือกจากรายชื่อในช้อยเดียวกันได้เลย
3. **หนังสือรับ — จัดวางเลขรับ/วันที่รับ/เวลารับใหม่**: แยกเป็น 3 ช่องเดี่ยวๆ ชัดเจน มีป้ายกำกับของตัวเอง (แทนที่จะเป็นข้อความยาวรวมกันช่องเดียว) ทั้งในกล่องพรีวิวก่อนบันทึก และในหน้าต่างยืนยันหลังบันทึกสำเร็จ ให้ดูง่ายสบายตาขึ้น

## เวอร์ชัน 16: แก้บั๊กปุ่ม "+" ในหนังสือส่งไม่ขึ้นเมื่อเลือก "อื่นๆ (ระบุ)"

1. **สาเหตุของปัญหา**: ตอนเลือก "อื่นๆ (ระบุ)" ในช่อง "ถึง" ระบบจะเคลียร์ค่าที่เก็บไว้ในช่องนั้นให้เป็นค่าว่างทันที (เพื่อรอให้พิมพ์เอง) แต่ก่อนหน้านี้ตัวเลือกที่แสดงในช้อย (dropdown) คำนวณมาจากค่าที่เก็บไว้นั้นโดยตรง พอค่าถูกเคลียร์เป็นค่าว่าง หน้าจอเลยเข้าใจผิดว่า "ยังไม่ได้เลือกอะไร" ทำให้ช้อยเด้งกลับไปที่ "-- เลือก --" และปุ่ม "+ เพิ่มช่องพิมพ์เอง" ไม่ขึ้นมาให้กดเลย (เป็นบั๊กที่มีมาตั้งแต่ก่อนเวอร์ชัน 15 ไม่ได้เพิ่งเกิดจากการแก้ไขล่าสุด)
2. **วิธีแก้**: แยกสถานะ "กำลังเลือกโหมดอื่นๆ อยู่หรือไม่" ออกมาเก็บต่างหาก ไม่ผูกกับค่าที่เก็บในช่องโดยตรงอีกต่อไป ทำให้ช้อยแสดงผล "อื่นๆ (ระบุ)" ค้างอยู่ถูกต้อง และปุ่ม "+" ปรากฏขึ้นมาให้กดตามปกติ ทดสอบแล้วว่ากดเลือก "อื่นๆ" → ปุ่ม "+" ขึ้น → กดปุ่ม → ช่องพิมพ์เองปรากฏ → พิมพ์ข้อความได้ตามลำดับ ครบถ้วนถูกต้อง
3. ผลกระทบเป็นการแก้ไขเฉพาะฝั่งหน้าจอ (React component) เท่านั้น ไม่มีการเปลี่ยนกฎ Firestore หรือโครงสร้างข้อมูลใดๆ

## เวอร์ชัน 17: เพิ่มระบบ "ค้นหา Target ID ไลน์อัตโนมัติ" (Webhook) — ทำต่อจากขั้นตอนสมัคร Messaging API เสร็จแล้ว

หลังจากสมัคร LINE Official Account และเปิดใช้งาน Messaging API แล้ว (มี Channel ID + Channel secret ตามภาพหน้าจอ) ขั้นตอนที่เหลือคือ **หา Channel access token** และ **หา Target ID** ของกลุ่ม/บุคคลปลายทาง เวอร์ชันนี้เพิ่มเครื่องมือช่วยหา Target ID ให้อัตโนมัติ ไม่ต้องไปไล่ดู Cloud Functions Logs เอง

1. เพิ่ม Cloud Function ใหม่ชื่อ `lineWebhook` ในโฟลเดอร์ `functions/` — ทำหน้าที่รับข้อความ/เหตุการณ์ที่ LINE ส่งเข้ามา (เช่น มีคนพิมพ์ข้อความ หรือเชิญบอทเข้ากลุ่ม) แล้วบันทึก Target ID ที่เจอไว้ในฐานข้อมูล
2. เพิ่มส่วนแสดงผล **"Target ID ที่ตรวจพบล่าสุด"** ในหน้า "ตั้งค่าระบบ" ใต้ช่อง Target ID เดิม — พอมี Target ID เข้ามา จะขึ้นเป็นรายการให้กด **"ใช้ Target ID นี้"** เพื่อกรอกลงช่องด้านบนอัตโนมัติ ไม่ต้องพิมพ์เอง
3. **ขั้นตอนที่ต้องทำต่อจากนี้ (ตามลำดับ)**:
   1. **ออก Channel access token**: ในหน้า Messaging API (หน้าเดียวกับภาพหน้าจอที่ส่งมา) เลื่อนลงมาด้านล่างสุด จะมีหัวข้อ **"Channel access token"** (แยกจาก "ความลับแชนแนล" ที่มีอยู่แล้ว) กดปุ่ม **"ออก"**/"Issue" เพื่อสร้างแบบ long-lived แล้วกด **"คัดลอก"** เก็บไว้ (โชว์ให้ดูครั้งเดียว)
   2. **ติดตั้ง Cloud Function**: ที่เครื่องคอมพิวเตอร์ที่มีโฟลเดอร์โปรเจกต์นี้ (แตกไฟล์ zip ที่ส่งให้แล้ว) เปิด Terminal/Command Prompt รันตามลำดับ:
      - `npm install -g firebase-tools` แล้ว `firebase login` (ถ้ายังไม่เคยทำ)
      - ที่โปรเจกต์ต้องอัปเกรดเป็นแพ็กเกจ **Blaze** ก่อน (Firebase Console → เลือกโปรเจกต์ `nsn-phc-web` → Upgrade) ปริมาณการใช้งานระดับหน่วยงานเล็กแบบนี้ไม่น่าเกินโควตาฟรี
      - รันคำสั่ง `firebase deploy --only functions` ที่โฟลเดอร์โปรเจกต์ รอจนเสร็จ จะได้ URL ของฟังก์ชัน 2 อันขึ้นมา (`onLeaveCreated`, `onLeaveUpdated`) และอันใหม่ **`lineWebhook`** — คัดลอก URL ของ `lineWebhook` เก็บไว้ (หน้าตาประมาณ `https://lineWebhook-xxxxxxxxx-uc.a.run.app` หรือ `https://us-central1-nsn-phc-web.cloudfunctions.net/lineWebhook`)
   3. **ตั้งค่า Webhook ที่ LINE**: กลับไปหน้า Messaging API เดิม (ภาพที่ส่งมา) วาง URL ของ `lineWebhook` ลงในช่อง **"ลิงก์ Webhook"** แล้วกด **"บันทึก"** จากนั้นเลื่อนหาสวิตช์ **"Use webhook"** เปิดให้เป็นสถานะ **ใช้งาน**
   4. **เชิญบอทเข้ากลุ่ม/เพิ่มเป็นเพื่อน**: สแกน QR Code ของบัญชี (ดูได้ที่หน้าแรกของ [LINE Official Account Manager](https://manager.line.biz/)) เพื่อเพิ่มเป็นเพื่อน หรือเชิญเข้ากลุ่มไลน์ที่ต้องการให้แจ้งเตือน
   5. **พิมพ์ข้อความทดสอบ**: พิมพ์อะไรก็ได้ 1 ข้อความในแชท/กลุ่มที่เพิ่งเพิ่มบอทเข้าไป (เช่น "ทดสอบ")
   6. **กลับมาหน้าเว็บ "ตั้งค่าระบบ"** รีเฟรชหน้า จะเห็น Target ID ขึ้นในรายการ "Target ID ที่ตรวจพบล่าสุด" พร้อมข้อความล่าสุดให้เช็คว่าใช่กลุ่ม/คนที่ต้องการ กด **"ใช้ Target ID นี้"**
   7. วาง **Channel access token** (จากขั้นตอน 1) ลงในช่องด้านบน เปิดสวิตช์ **"เปิดใช้งานแจ้งเตือนไลน์"** เลือกเหตุการณ์ที่ต้องการแจ้งเตือน แล้วกด **"บันทึก"**
   8. ทดสอบโดยยื่นใบลา 1 ใบ หรือกดอนุมัติ/ไม่อนุมัติใบลาที่มีอยู่ ข้อความควรเด้งเข้ากลุ่ม/แชทไลน์ภายในไม่กี่วินาที
4. **หมายเหตุความปลอดภัย**: ฟังก์ชัน `lineWebhook` ไม่ได้ตรวจลายเซ็นของ LINE (เพื่อความง่าย) เพราะใช้แค่ "รับฟัง" หา Target ID ชั่วคราวเท่านั้น ไม่มีผลต่อข้อมูลจริงในระบบ หลังจากตั้งค่า Target ID ที่ต้องการเรียบร้อยแล้ว จะยังคงเปิด Webhook นี้ทิ้งไว้ก็ได้ (ไม่กระทบอะไร) หรือจะปิดสวิตช์ "Use webhook" ทีหลังก็ได้เช่นกัน — ไม่มีผลต่อการส่งแจ้งเตือนออก เพราะการส่งออกใช้ `sendLine()`/Messaging API push แยกต่างหาก ไม่เกี่ยวกับ Webhook

## เวอร์ชัน 18: ปุ่ม "อนุมัติ/ไม่อนุมัติ" ในไลน์กลุ่ม + ลิงก์พิมพ์ใบลาอัตโนมัติ (เฉพาะผู้อำนวยการ)

เวอร์ชันนี้ทำตามคำขอ: เมื่อมีคนยื่นใบลา ให้ข้อความที่ส่งเข้าไลน์กลุ่มมีปุ่ม **"✅ อนุมัติ"** / **"❌ ไม่อนุมัติ"** ติดมาด้วยเลย โดยกดได้เฉพาะผู้อำนวยการเท่านั้น พอกดอนุมัติแล้ว ระบบจะเปลี่ยนสถานะใบลาให้อัตโนมัติ พร้อมส่งลิงก์สำหรับเปิดพิมพ์ใบลา (บันทึกเป็น PDF/ปริ้นกระดาษได้ทันที) กลับเข้ากลุ่มอีกครั้ง

1. **การ์ดขออนุมัติแบบมีปุ่ม (Flex Message)**: ตอนยื่นใบลาใหม่ (`onLeaveCreated`) แทนที่จะส่งข้อความธรรมดา ระบบจะส่งเป็นการ์ด สรุปชื่อ-ตำแหน่ง-ประเภทการลา-วันที่-เหตุผล พร้อมปุ่ม **✅ อนุมัติ** (สีเขียว) และ **❌ ไม่อนุมัติ** (สีแดง) ท้ายการ์ด
2. **ตรวจสิทธิ์ผู้กดปุ่ม**: เมื่อมีคนกดปุ่มในไลน์ (ส่งมาเป็นเหตุการณ์ `postback` เข้า `lineWebhook`) ระบบจะเทียบ LINE User ID ของคนกดกับ **`directorUserId`** ที่บันทึกไว้ในระบบ — ถ้าไม่ตรงกัน จะตอบกลับในแชทว่า "ปุ่มนี้ใช้ได้เฉพาะผู้อำนวยการเท่านั้น" และไม่เปลี่ยนสถานะใบลาใดๆ ทั้งสิ้น ถ้ายังไม่เคยตั้งค่า `directorUserId` เลย จะตอบกลับเตือนให้ไปตั้งค่าก่อน
3. **เมื่อกดอนุมัติสำเร็จ**: ระบบอัปเดตสถานะใบลาในฐานข้อมูลเป็น "อนุมัติ" หรือ "ไม่อนุมัติ" ทันที (พร้อมบันทึกว่า `decidedBy: "ผู้อำนวยการ (ผ่านไลน์)"`) แล้วตอบกลับยืนยันในแชท จากนั้น `onLeaveUpdated` (ของเดิม) จะทำงานต่ออัตโนมัติ ส่งข้อความ "ผลการพิจารณาใบลา" เข้ากลุ่มเหมือนเดิม — แต่ถ้าผลเป็น **"อนุมัติ"** จะแนบ **ลิงก์พิมพ์ใบลา** (`/#/print-leave/<รหัสใบลา>`) ต่อท้ายให้ด้วย เปิดลิงก์นี้แล้วกด "พิมพ์ / บันทึกเป็น PDF" ได้เลย (ต้องล็อกอินเข้าเว็บระบบก่อนถึงจะเปิดได้ ตามสิทธิ์การเข้าถึงเดิมของระบบ)
4. **ตั้งค่าผู้อำนวยการ (ทำครั้งเดียว)**: ในหน้า "ตั้งค่าระบบ" ผู้อำนวยการต้องพิมพ์ข้อความคุยกับบอทเป็นการส่วนตัว (แชท 1:1 ไม่ใช่ในกลุ่ม) อย่างน้อย 1 ครั้งก่อน เพื่อให้ LINE User ID ของผู้อำนวยการไปปรากฏในรายการ "Target ID ที่ตรวจพบล่าสุด" (จะขึ้นเป็นประเภท "รายบุคคล") จากนั้นกดปุ่ม **"ตั้งเป็นผู้อำนวยการ"** ข้างรายการนั้น ระบบจะบันทึก LINE User ID นี้เป็น `directorUserId` ไว้ตรวจสิทธิ์ปุ่มอนุมัติต่อไป (ตั้งใหม่ได้เสมอถ้าต้องเปลี่ยนตัวผู้อนุมัติ)
5. **ไฟล์ที่แก้ไข**: `functions/index.js` (เพิ่ม `buildLeaveApprovalFlex`, `handleLeavePostback`, แก้ `onLeaveCreated`/`onLeaveUpdated`), `src/lib/lineNotify.js` (เพิ่ม `saveLineDirectorId`, แก้ `saveLineMeta` ให้รักษาค่า `directorUserId` เดิมไว้เวลาบันทึกซ้ำ), `src/pages/SettingsPage.jsx` (แสดงสถานะผู้อำนวยการปัจจุบัน + ปุ่ม "ตั้งเป็นผู้อำนวยการ")
6. **ต้อง deploy ทั้งสองส่วน**: เวอร์ชันนี้แก้ทั้งฝั่งเว็บ (frontend) และฝั่ง Cloud Functions (backend) จึงต้องอัปเดต **ทั้งสองทาง** — อัปโหลดไฟล์ขึ้น GitHub ตามปกติ (ให้ GitHub Actions บิลด์เว็บ) **และ** รันคำสั่ง `firebase deploy --only functions` จากเครื่องคอมพิวเตอร์อีกรอบหนึ่งด้วย ไม่งั้นปุ่มจะยังไม่ขึ้นในไลน์

## เวอร์ชัน 19: เมนูรายงาน/สถิติการลา (ทะเบียนคุม + สถิติ, ส่งออก Excel/PDF) + บล็อกยื่นใบลาเกินระเบียบ

เพิ่มเมนูใหม่ **"รายงาน/สถิติการลา"** (หมวด "แผนงานและรายงาน") ตามคำขอ: ทะเบียนคุมการลา, ทะเบียนรวมการลา, สถิติการลารายบุคคล, สถิติการลารวมทุกคน — ทุกรายงานนับตามปีงบประมาณ (1 ต.ค. - 30 ก.ย. เดิมของระบบอยู่แล้ว) ส่งออกได้ทั้ง Excel และพิมพ์ PDF เก็บเข้าแฟ้ม พร้อมขยายการบล็อก/แจ้งเตือนการยื่นใบลาเกินระเบียบให้ครบทุกประเภทลา

1. **หน้ารายงานใหม่** (`src/pages/LeaveReports.jsx`, เมนู "รายงาน/สถิติการลา" 📊) มี 4 แท็บ:
   - **ทะเบียนคุมการลา (รายบุคคล)**: ประวัติการลาทั้งหมดของคนใดคนหนึ่งในปีงบประมาณที่เลือก เรียงตามวันที่ (ดูของตัวเองได้ทุกคน ส่วนผู้มีสิทธิ์ "ดูวันลาทุกคน" เลือกดูของคนอื่นได้ด้วย)
   - **ทะเบียนรวมการลา (ทุกคน)**: รวมใบลาทุกคนในปีงบประมาณเดียวกันไว้ตารางเดียว (เฉพาะผู้มีสิทธิ์ "ดูวันลาทุกคน": Super Admin/ผู้อำนวยการ/งานธุรการ)
   - **สถิติการลา (รายบุคคล)**: ตารางสรุปต่อประเภทลา (โควตา/ปี, ใช้แล้ว, รออนุมัติ, คงเหลือ, จำนวนครั้ง) ของคนที่เลือก
   - **สถิติการลารวม (ทุกคน)**: ตาราง matrix คน × ประเภทลา (นับเฉพาะที่อนุมัติแล้ว) พร้อมยอดรวมต่อคน (เฉพาะผู้มีสิทธิ์ "ดูวันลาทุกคน")
2. **ส่งออก Excel**: ปุ่ม "ส่งออก Excel" ทุกแท็บ ใช้ตัวช่วยเดิมของระบบ (`exportXlsx`) ได้ไฟล์ `.xlsx` ชื่อไฟล์ระบุรายงาน+ปีงบประมาณอัตโนมัติ
3. **พิมพ์ PDF**: ปุ่ม "พิมพ์ PDF" เปิดหน้าพิมพ์ใหม่ (`src/pages/PrintLeaveReport.jsx`, เส้นทาง `/print-leave-report/:kind`) จัดหน้าแบบตารางพร้อมโลโก้/ชื่อหน่วยงาน เหมือนหน้าพิมพ์ทะเบียนอื่น ๆ ของระบบ กด "พิมพ์ / บันทึกเป็น PDF" เพื่อเก็บไฟล์หรือปริ้นกระดาษได้ทันที
4. **ขยายโควตาการลาตามระเบียบให้ครบ** (`src/lib/leave.js`, `DEFAULT_QUOTA`) เพิ่ม 2 ประเภทที่ระเบียบสำนักนายกรัฐมนตรีกำหนดเพดานไว้แต่ระบบยังไม่เคยตั้งค่าเริ่มต้นให้: **ลาไปช่วยเหลือภริยาที่คลอดบุตร ไม่เกิน 15 วันทำการ** และ **ลาอุปสมบท/ประกอบพิธีฮัจย์ ไม่เกิน 120 วัน** (ปรับแก้ตัวเลขได้ที่เมนู "ตั้งค่าระบบ" เหมือนเดิม)
5. **แจ้งเตือน + บล็อกยื่นใบลาเกินระเบียบ**: ระบบบล็อกการยื่นใบลาเกินโควตาอยู่แล้วตั้งแต่เดิม เวอร์ชันนี้เพิ่ม **กล่องแจ้งเตือนแบบเรียลไทม์** ในฟอร์มยื่นใบลา (`src/pages/Leave.jsx`) แสดงสิทธิ์คงเหลือของประเภทที่เลือกทันทีที่กรอกวันที่/จำนวนวัน และจะขึ้นข้อความสีแดง **"⚠️ เกินสิทธิ์ตามระเบียบ"** พร้อมปิดปุ่ม "ยื่นใบลา" ทันทีถ้าจำนวนวันที่จะยื่น (รวมที่ใช้ไปแล้ว/รออนุมัติ) เกินโควตา — กันไว้ตั้งแต่ก่อนกดยื่น ไม่ต้องรอ error ตอนบันทึก
6. **ไม่กระทบ Cloud Functions**: เวอร์ชันนี้แก้เฉพาะฝั่งเว็บ (frontend) เท่านั้น จึงอัปโหลดไฟล์ขึ้น GitHub ตามปกติแล้วรอ GitHub Actions บิลด์เสร็จได้เลย **ไม่ต้อง** รัน `firebase deploy --only functions` รอบนี้

## เวอร์ชัน 20: ปฏิทินมอบหมายงาน + แจ้งเตือนเข้าไลน์กลุ่มอัตโนมัติทุกวัน 06:00 น.

เพิ่มเมนูใหม่ **"🗂️ ปฏิทินมอบหมายงาน"** (หมวด "แผนงานและรายงาน") ตามคำขอ: ลงเรื่องมอบหมายงาน (ประชุม/งานอบรม/หน่วยปฐมพยาบาล/อื่น ๆ พิมพ์เอง) ลงวันที่ล่วงหน้าได้ พร้อมเลือกผู้ปฏิบัติงานได้หลายคน ระบบจะแจ้งเตือนเข้าไลน์กลุ่มอัตโนมัติทุกวันเวลา **06:00 น.** เฉพาะวันที่มีการมอบหมายงานไว้เท่านั้น

1. **หน้าใหม่** (`src/pages/Assignments.jsx`, เมนู "ปฏิทินมอบหมายงาน") — เลือกดูรายเดือน (ปุ่ม ◀ ▶ หรือเลือกเดือนตรงๆ) มีตัวกรอง "เฉพาะงานที่มอบหมายให้ฉัน" ทุกคนที่ยังไม่ถูกระงับสิทธิ์ดูได้ ส่วนเพิ่ม/แก้ไข/ลบจำกัดเฉพาะ Super Admin/งานธุรการ/ผู้อำนวยการ (ตรงกับสิทธิ์ระดับเดียวกับทะเบียนควบคุมยานพาหนะ/แผนเวรนอกเวลา)
2. **ฟอร์มเพิ่มการมอบหมายงาน**: วันที่ปฏิบัติงาน, เวลา/สถานที่ (ไม่บังคับ), ประเภทงาน (เลือก "อื่น ๆ (ระบุเอง)" แล้วพิมพ์เองได้), เรื่อง/รายละเอียดงาน, เลือกผู้ปฏิบัติงานได้หลายคนจากทำเนียบบุคลากร, หมายเหตุ
3. **คอลเลกชันข้อมูลใหม่**: `assignments` (วันที่, ประเภท, เรื่อง, เวลา, สถานที่, รายชื่อผู้ปฏิบัติงาน, หมายเหตุ, ผู้บันทึก) — เพิ่มสิทธิ์ในทั้ง `src/lib/roles.js` (`ACCESS.assignments`) และ **`firestore.rules`** (`match /assignments/{id}`)
4. **Cloud Function ใหม่** (`functions/index.js` → `exports.dailyAssignmentReminder`) ใช้ `onSchedule` ตั้งเวลาทำงานทุกวัน **06:00 น. เวลาไทย** (`timeZone: 'Asia/Bangkok'`) — ตรวจว่าวันนี้มีรายการในปฏิทินมอบหมายงานหรือไม่ ถ้ามีจะรวมทุกรายการของวันนั้นเป็นข้อความเดียวส่งเข้ากลุ่มไลน์ (ชื่องาน/เวลา/สถานที่/ผู้ปฏิบัติงาน/หมายเหตุ) ถ้าวันนั้นไม่มีรายการจะไม่ส่งข้อความใดๆ ทั้งสิ้น (ใช้ Channel access token/Target ID/สวิตช์เปิดใช้งานชุดเดียวกับแจ้งเตือนวันลาที่ตั้งค่าไว้แล้ว)
5. **สวิตช์เปิด/ปิดแยกต่างหาก**: หน้า "ตั้งค่าระบบ" เพิ่มช่องติ๊ก **"ปฏิทินมอบหมายงาน (ทุกวัน 06:00 น.)"** ในส่วนแจ้งเตือนไลน์ (เปิดให้ค่าเริ่มต้นเป็นเปิดใช้งาน ปิดได้ถ้าไม่ต้องการ)
6. **ต้องอัปเดตครบ 3 ส่วน** (สำคัญ): เวอร์ชันนี้แก้ทั้งฝั่งเว็บ, `firestore.rules`, และ Cloud Functions พร้อมกัน จึงต้องทำครบทั้ง 3 ขั้นตอน:
   1. อัปโหลดไฟล์ขึ้น GitHub ตามปกติ (ให้ GitHub Actions บิลด์เว็บ)
   2. **Firebase Console → Firestore Database → Rules** วางเนื้อหาไฟล์ `firestore.rules` ใหม่ทั้งหมด → กด **Publish**
   3. รันคำสั่ง `firebase deploy --only functions` จากเครื่องคอมพิวเตอร์ (Administrator Command Prompt เหมือนเดิม) เพื่อติดตั้งฟังก์ชัน `dailyAssignmentReminder` — ข้อ 2 และ 3 ถ้าขาดไปข้อใดข้อหนึ่ง หน้าปฏิทินจะเปิดไม่ได้ (ติด permission) หรือแจ้งเตือน 06:00 น. จะยังไม่ทำงาน

## เวอร์ชัน 21: ปฏิทินมอบหมายงานเป็นปฏิทินไทย, แก้บั๊กแจ้งเตือน 06:00 น. ไม่เข้าไลน์, ปุ่มรีเซ็ตรหัสผ่านทุกคนพร้อมกัน

แก้ 3 เรื่องตามที่แจ้ง:

1. **ปฏิทินมอบหมายงานเป็นปฏิทินไทย**: เปลี่ยนตัวเลือก "เดือน/ปี" ของหน้า "🗂️ ปฏิทินมอบหมายงาน" จากปฏิทินอังกฤษ/คริสต์ศักราชของเบราว์เซอร์ เป็นช่องเลือก **ชื่อเดือนภาษาไทย** + **ปี พ.ศ.** โดยตรง (`src/pages/Assignments.jsx`)
2. **แก้บั๊กแจ้งเตือนปฏิทินมอบหมายงาน 06:00 น. ไม่เข้าไลน์กลุ่ม**: สาเหตุคือโค้ดรวมค่าตั้งค่าที่บันทึกไว้เดิม (จากก่อนเพิ่มฟีเจอร์นี้) ทับค่าเริ่มต้นแบบผิดวิธี ทำให้ระบบมองว่าสวิตช์ "ปฏิทินมอบหมายงาน" ถูกปิดอยู่เงียบๆ ทั้งที่หน้าตั้งค่าไม่ได้ติ๊กปิดไว้ — แก้ไขทั้งฝั่งเว็บ (`src/lib/lineNotify.js`) และฝั่ง Cloud Function (`functions/index.js`) ให้รวมค่าเริ่มต้นถูกต้อง **แก้แล้วจะใช้งานได้ทันทีหลัง deploy functions ใหม่ ไม่ต้องเข้าไปกดบันทึกหน้าตั้งค่าซ้ำ**
3. **ปุ่ม "รีเซ็ตรหัสผ่านทุกคน" (เฉพาะ Super Admin)**: หน้า "ทำเนียบบุคลากร" เพิ่มปุ่มใหม่ให้ Super Admin ตั้งรหัสผ่านใหม่ค่าเดียวกันให้ผู้ใช้งาน **ทุกคนพร้อมกันในคลิกเดียว** (ยกเว้น Super Admin เอง และบัญชี "รอสมัครใหม่" ที่ยังไม่อนุมัติ) โดย **Username เดิมของแต่ละคนไม่เปลี่ยนแปลง** — ทุกคนจะถูกบังคับให้ตั้งรหัสผ่านใหม่เองตอนล็อกอินครั้งถัดไปตามปกติ (เหมือนฟีเจอร์ "ตั้งรหัสเริ่มต้นใหม่" ที่มีอยู่แล้ว)

   2. รันคำสั่ง `firebase deploy --only functions` จากเครื่องคอมพิวเตอร์ (Administrator Command Prompt เหมือนเดิม) เพื่อติดตั้งฟังก์ชัน `adminBulkResetPassword` ใหม่ และอัปเดตฟังก์ชัน `dailyAssignmentReminder` ที่แก้บั๊กแล้ว — ถ้าขาดขั้นตอนนี้ ปุ่ม "รีเซ็ตรหัสผ่านทุกคน" จะกดไม่ได้ (ขึ้น error) และแจ้งเตือน 06:00 น. จะยังไม่ถูกแก้

## เวอร์ชัน 27: ปฏิทินเลือกวันที่เป็น พ.ศ. ล้วนทุกทะเบียน, หัวข้อหลักเมนูซ้ายเป็นตัวอักษรขาวตัดกับสีฟ้า, แทรกเลขที่ทะเบียนย้อนหลังได้ทุกทะเบียน

(เวลาไทย) — ระบบจะตรวจทุกเช้าว่าวันนี้ตรงกับวันเกิด (เทียบเฉพาะวัน/เดือน ไม่สนปีเกิด) ของใครบ้าง ถ้ามีจะส่งคำอวยพรพร้อมอิโมจิน่ารักๆ เข้ากลุ่มไลน์ให้อัตโนมัติ (สุ่มข้อความอวยพรสลับไปแต่ละครั้งไม่ให้ซ้ำเดิมทุกปี) — เปิด/ปิดการแจ้งเตือนนี้ได้ที่หน้า **"ตั้งค่าระบบ" → แจ้งเตือนไลน์** เหมือนเหตุการณ์อื่นๆ (เปิดเป็นค่าเริ่มต้นไว้ให้แล้ว)
3. ใครยังไม่กรอกวันเกิดไว้ จะไม่มีการแจ้งเตือนให้ (ต้องให้ Super Admin เข้าไปกรอกที่ทำเนียบบุคลากรก่อน)

**การอัปเดตรอบนี้ต้องทำ 2 ขั้นตอน** (ต้อง deploy Cloud Functions ใหม่ เพราะเพิ่มฟังก์ชันแจ้งเตือนไลน์ใหม่ 1 ฟังก์ชัน ไม่ต้องแก้ไฟล์สิทธิ์):
1. อัปโหลดไฟล์ขึ้น GitHub ตามปกติ
2. เปิด Terminal ที่เครื่องคอมพิวเตอร์ของตัวเอง (ไม่ใช่ทำผ่าน Console) เข้าไปที่โฟลเดอร์โปรเจกต์แล้วรันคำสั่ง `firebase deploy --only functions` รอจนรันเสร็จ — ฟังก์ชันแจ้งเตือนวันเกิด (`dailyBirthdayReminder`) จะยังไม่ทำงานจนกว่าจะรันคำสั่งนี้สำเร็จ
