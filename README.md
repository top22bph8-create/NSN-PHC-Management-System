# ระบบบริหารงาน รพ.สต.บ้านหนองสนม

เว็บแอปบริหารงานภายใน (React + Vite + Tailwind + Firebase) เผยแพร่ผ่าน GitHub Pages

## ฟีเจอร์รอบที่ 1
- ล็อกอิน + สิทธิ์ตามบทบาท (Super Admin, ผอ., ธุรการ, การเงิน, พัสดุ, ควบคุมโรค, เวชปฏิบัติฯ, ผู้ดูรายงาน)
- Dashboard, ค้นหาแบบรวม, เลือกปีงบประมาณจากส่วนกลาง
- ทะเบียนหนังสือรับ/ส่ง: เพิ่ม แก้ไข ค้นหา กรอง ดูรายละเอียด แนบไฟล์ (PDF/Word/Excel/รูป) ลบพร้อมยืนยัน ส่งออก Excel/CSV
- เลขทะเบียนอัตโนมัติ (เช่น 001/2569) ตั้งรูปแบบได้ ขึ้นปีใหม่เริ่มใหม่
- Audit Log (ใคร ทำอะไร เมื่อไร ข้อมูลเดิม/ใหม่)
- โมดูลอื่นในเมนูแสดงเป็น "เร็วๆ นี้"

## ตั้งค่าครั้งแรก
1. อัปโหลดไฟล์ทั้งหมดขึ้น GitHub (ไม่รวม node_modules)
2. GitHub → Settings → Pages → Source เลือก **GitHub Actions**
3. Firebase Console → Firestore → Rules วางเนื้อหาไฟล์ `firestore.rules` → Publish
4. Firebase Console → Storage → Get started → Rules วางเนื้อหาไฟล์ `storage.rules` → Publish
5. Firebase Console → Authentication → Settings → User actions → **ปิด** "Enable create (sign-up)"
6. เข้าเว็บด้วยอีเมลเจ้าของระบบ ครั้งแรกระบบสร้างสิทธิ์ Super Admin ให้อัตโนมัติ

## เพิ่มผู้ใช้
สร้างบัญชีที่ Firebase Authentication → Add user แล้วเพิ่มสิทธิ์ในเมนู "ผู้ใช้งานและสิทธิ์"

## พัฒนาต่อในเครื่อง
```
npm install
npm run dev
npm run build
```

## ความปลอดภัย
- ห้ามใส่ข้อมูลผู้ป่วยหรือข้อมูลสุขภาพในที่เก็บโค้ดนี้ (เป็น Public) ข้อมูลทั้งหมดอยู่ใน Firebase
- ค่า `firebaseConfig` ใน `src/firebase.js` เปิดเผยได้ ความปลอดภัยอยู่ที่ Rules
- ข้อมูลผู้รับบริการ (เวชปฏิบัติครอบครัว) ยังไม่เปิดใช้ ต้องออกแบบสิทธิ์และ PDPA ก่อน

## เวอร์ชัน 2: โลโก้/ธีมฟ้าอ่อน, บุคลากร, วันลา, สำรองข้อมูล

1. อัปโหลดทับของเดิม: ลากโฟลเดอร์ `src` และ `public` ทั้งโฟลเดอร์ + `index.html` + `firestore.rules`
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ แล้วกด Publish
3. นำเข้าบุคลากร: ล็อกอินด้วย Gmail เจ้าของระบบ → "ทำเนียบบุคลากร" → "นำเข้า Excel"
   (ก่อนนำเข้าเปิด Authentication → Settings → User actions → Enable create (sign-up) และปิดกลับหลังเสร็จ)
4. ผู้ใช้ล็อกอินด้วย Username (เช่น 1) และรหัสผ่านตามไฟล์ แล้วระบบบังคับตั้งรหัสใหม่ (8 ตัวขึ้นไป มีตัวอักษรและตัวเลข)
   รหัสที่สั้นกว่า 6 ตัว ระบบต่อท้าย `#nsn` ให้อัตโนมัติ
5. ห้ามนำไฟล์ Excel ที่มีรหัสผ่านขึ้น GitHub

## เวอร์ชัน 3: ปีงบประมาณ 2570, เลขหนังสือส่งรูปแบบใหม่, เมนูใหม่, ยานพาหนะ/แผนงาน

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html`, `firestore.rules`, `storage.rules` ครบ
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ → Publish
3. Firebase → Storage → Rules: วางเนื้อหา `storage.rules` ใหม่ → Publish
4. ปีงบประมาณ: ระบบเริ่มนับตั้งแต่ปีงบประมาณ 2570 (1 ต.ค. 2569) เป็นต้นไป จะไม่มีปีเก่ากว่านี้ให้เลือก
5. เลขหนังสือส่ง: ออกเป็น "สน 51006.24/ลำดับ" อัตโนมัติ รันต่อเนื่องทั้งปีงบประมาณ
   - ถ้าลงวันที่ย้อนหลังและเลขที่นั้นถูกใช้ไปแล้ว ให้ติ๊ก "แทรกเลขที่ย้อนหลัง" ตอนเพิ่มหนังสือส่ง แล้วเลือกเลขที่เดิม ระบบจะออกเลขให้เป็น /20.1, /20.2 ตามลำดับ
6. เมนูใหม่: ทะเบียนควบคุมยานพาหนะ, แผนเวรนอกเวลาประจำเดือน, แผน/รายงานเยี่ยมบ้านเชิงรุกประจำเดือน (ตั้งค่าเลขทะเบียน/สิทธิ์เพิ่มเติมได้ที่หน้า "ตั้งค่าระบบ")

## เวอร์ชัน 4: เมนูรายงาน Excel/PDF, สมัครสมาชิกด้วยตนเอง, ทะเบียนหนังสือส่งช่อง "ถึง", ธีมฟ้าทันสมัย, วันลารายบุคคล

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html`, `firestore.rules`, `storage.rules` ครบ
2. Firebase → Firestore → Rules: วางเนื้อหา `firestore.rules` ใหม่ → Publish (เพิ่มกฎอนุญาตให้ผู้สมัครใหม่สร้างโปรไฟล์ตัวเองสถานะรออนุมัติ)
3. **สำคัญ: เปิด Firebase Console → Authentication → Settings → User actions → "Enable create (sign-up)" ค้างไว้ถาวร** (ต่างจากเวอร์ชันก่อนที่ให้เปิดชั่วคราวตอนนำเข้ารายชื่อ) เพราะหน้า "สมัครใช้งาน" (/#/signup) ต้องใช้ฟังก์ชันนี้สร้างบัญชีให้ผู้ใช้เองตลอดเวลา
4. **สมัครใช้งาน/อนุมัติผู้ใช้**: ผู้ใช้ใหม่กดลิงก์ "ยังไม่มีบัญชี? สมัครใช้งาน" ที่หน้าล็อกอิน ตั้ง Username/รหัสผ่านเอง ระบบจะส่งคำขอเป็นสถานะ "รอผู้ดูแลระบบอนุมัติ" ไปที่เมนู "ทำเนียบบุคลากร" (มีแถบสีส้ม "รอสมัครใหม่" ให้สังเกตง่าย) ผู้ดูแลระบบเลือกบทบาทแล้วติ๊ก "ใช้งาน" เพื่ออนุมัติ หรือแก้ไข/ตั้งรหัสใหม่ได้ตามปกติ
5. **ทะเบียนหนังสือส่ง**: เลขที่หนังสือส่งที่จะออกแสดงในช่องแบบฟอร์มให้เห็นชัดเจนก่อนบันทึก และเปลี่ยนช่อง "ผู้รับ"/"ปลายทาง" เดิมเป็นช่อง "ถึง" แบบเลือกจากรายการที่กำหนดไว้ (พร้อมตัวเลือก "อื่นๆ" ให้พิมพ์เองได้)
6. **เมนูรายงาน**: แต่ละทะเบียน (หนังสือรับ/ส่ง, ยานพาหนะ, เวรนอกเวลา, เยี่ยมบ้าน) มีปุ่ม "รายงาน Excel" (ไฟล์ .xlsx ลายแถบสีแบบทะเบียนราชการ ดาวน์โหลดได้ทันที) และ "รายงาน PDF" (เปิดหน้าพิมพ์ในแท็บใหม่ แล้วใช้ฟังก์ชัน "พิมพ์" ของเบราว์เซอร์ เลือกปลายทางเป็น **"บันทึกเป็น PDF" / "Save as PDF"** — เป็นการพิมพ์ผ่านเบราว์เซอร์ ไม่ใช่ปุ่มดาวน์โหลด PDF โดยตรง เนื่องจากระบบนี้เป็นแอปฝั่งเว็บเบราว์เซอร์ล้วน ไม่มีเซิร์ฟเวอร์สร้างไฟล์ PDF)
   - หมายเหตุ: ตัวอย่างรายงานที่ส่งมา 8 แบบ มี 5 แบบ (คำสั่ง, ประกาศ, ใบสั่งซื้อ/สั่งจ้าง, สัญญาเงินยืม, หนังสือสัญญา) เป็นงานในหมวด "กลุ่มงานบริหาร" ที่ยังเป็น "เร็วๆ นี้" (ยังไม่มีทะเบียนบันทึกข้อมูลจริง) ต้องสร้างทะเบียนของงานเหล่านั้นก่อน จึงจะออกรายงานรูปแบบเดียวกันนี้ให้ได้
7. **ธีม**: ปรับโทนสีฟ้าทันสมัยขึ้น หัวเพจ (PageHeader) เป็นแถบฟ้าเข้มไล่สี หัวข้อเมนูงานหลัก (ทะเบียนหลัก, แผนงานและรายงาน) เป็นแถบสีตัวหนาใหญ่ในเมนูซ้าย แยกจากงานรองชัดเจน และเพิ่มอิโมจิสีสันประจำแต่ละงาน
8. **วันลารายบุคคล**: ในเมนู "ทะเบียนควบคุมวันลา" เพิ่มแท็บ "รายบุคคล" แสดงรายชื่อบุคลากรทั้งหมด (เห็นเฉพาะผู้อำนวยการ/ธุรการ/Super Admin) คลิกชื่อใครเพื่อดูแดชบอร์ดวันลาคงเหลือ/สถิติของคนนั้น พร้อมปุ่ม "ยื่นใบลา" เฉพาะบุคคล (ยื่นแทนผู้อื่นได้เฉพาะ Super Admin/ธุรการ ตามสิทธิ์เดิมของระบบ)

## เวอร์ชัน 5: ปรับรายงาน/ทะเบียนตามผลตอบรับ, ใบลา PDF ตามแบบฟอร์มจริง

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ (รอบนี้ไม่มีการแก้ `firestore.rules`/`storage.rules`)
2. **ปุ่มรายงาน**: แต่ละทะเบียนเหลือปุ่มส่งออกเพียงชุดเดียว คือ **CSV / Excel (ลายแถบสีทะเบียนราชการ) / PDF** (ตัดปุ่ม Excel แบบเรียบที่ซ้ำซ้อนออกแล้ว)
3. **ทะเบียนหนังสือส่ง**: ช่อง "ผู้รับผิดชอบ" เปลี่ยนเป็นดรอปดาวน์ดึงชื่อจากทำเนียบบุคลากรโดยอัตโนมัติ และช่องเลขที่แทรกย้อนหลังจะคำนวณ/แสดงเลขแทรกจริง (เช่น /20.1) ให้เห็นก่อนกดบันทึก แทนที่จะโชว์เป็นเครื่องหมาย "x" เหมือนก่อน
4. **ทะเบียนหนังสือรับ**: ตัดช่อง "กำหนดดำเนินการ" และ "วันที่ดำเนินการ" ออก, เมื่อกดบันทึกจะค้างหน้าต่างไว้ให้เห็นกล่อง "เลขรับ" และ "เวลาที่รับหนังสือ" ชัดเจนก่อนปิดเอง (ไฟล์แนบเก็บและค้นดูได้ตามเดิม เพราะระบบแนบไฟล์ใช้ร่วมกันทุกทะเบียนอยู่แล้ว)
5. **วันลารายบุคคล**: จัดเรียงรายชื่อตามลำดับตำแหน่ง (นักวิชาการสาธารณสุขชำนาญการพิเศษ → นักวิชาการสาธารณสุข → พยาบาลวิชาชีพ → แพทย์แผนไทย → ผู้ช่วยเหลือคนไข้ → พนักงานบริการ → พนักงานการเงินและบัญชี → คนขับรถ) ชื่อบุคลากรแสดงเด่นอยู่หน้าลิสต์เลย พร้อมแดชบอร์ดโควตาคงเหลือ/ใช้ไปแต่ละประเภทของแต่ละคน และปุ่ม "ยื่นใบลา" ท้ายแถวของแต่ละคน
6. **หัวข้อหน้าเพจ**: ปรับตัวหนังสือหัวข้อเป็นสีขาวทึบตัดกับแถบพื้นหลังสีฟ้าให้ชัดเจนขึ้น พร้อมอิโมจิกระพริบประจำแต่ละงาน
7. **ใบลา PDF ตามแบบฟอร์มจริง**: เพิ่มปุ่มพิมพ์ (ไอคอนเครื่องพิมพ์) ที่ท้ายแถวใบลาทุกใบ ทั้งในตารางรวมและในแดชบอร์ดรายบุคคล กดแล้วเปิดแท็บใหม่เป็นแบบฟอร์มใบลาให้ใช้ฟังก์ชัน "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์ โดยรูปแบบฟอร์มจะเปลี่ยนไปตามประเภทการลา:
   - ลาป่วย/ลากิจส่วนตัว/ลาคลอดบุตร → แบบฟอร์มรวม 3 ประเภท (มีช่องติ๊กประเภทที่เลือก) ตามตัวอย่างที่แนบ
   - ลาพักผ่อน → แบบใบลาพักผ่อน พร้อม "บันทึกข้อความ" หน้าที่สองสำหรับส่งเรื่องให้กองสาธารณสุขพิจารณา ตามตัวอย่างที่แนบ
   - ลาอุปสมบท/ประกอบพิธีฮัจย์ → แบบใบลาอุปสมบทตามตัวอย่าง (รายละเอียดเฉพาะทาง เช่น ชื่อวัด ให้กรอกด้วยลายมือในช่องเว้นว่าง เนื่องจากระบบยังไม่มีช่องเก็บข้อมูลเหล่านี้)
   - ประเภทลาอื่นๆ ที่ไม่มีตัวอย่างแนบมา (ลาไปช่วยเหลือภริยาคลอดบุตร/ลาไปศึกษาฝึกอบรม/อื่นๆ) → ใช้โครงร่างฟอร์มใกล้เคียงกันเป็นแบบมาตรฐานกลาง
   - หมายเหตุ: แบบฟอร์ม "ใบขอยกเลิกวันลา" ที่แนบมาเป็นตัวอย่างเพิ่มเติม ยังไม่ได้ทำเป็นหน้าพิมพ์แยกในรอบนี้ (ปัจจุบันการยกเลิกใบลาทำผ่านปุ่ม "ยกเลิก" ในตารางได้อยู่แล้ว แต่ยังไม่ออกเป็นเอกสาร PDF ตามแบบฟอร์ม)

## เวอร์ชัน 6: ปุ่มยกเลิกวันลาแบบเลือกช้อย (สิทธิ์เฉพาะ Super Admin), ใบลา PDF ตามแบบฟอร์มจริง 2 แผ่นทุกประเภท

1. อัปโหลดทับของเดิม: ต้องมี `src`, `public`, `index.html` ครบ **และรอบนี้ต้องนำ `firestore.rules` ไปเผยแพร่ใหม่ด้วย** (Firebase Console → Firestore Database → Rules หรือ `firebase deploy --only firestore:rules`) มิฉะนั้นสิทธิ์การยกเลิกวันลาจะยังเป็นแบบเดิม
2. **ปุ่ม "ยกเลิกวันลา" ในหัวทะเบียนควบคุมวันลา**: กดแล้วขึ้นหน้าต่างให้เลือกจากช้อยว่าจะยกเลิกใบลาใบไหน
   - **Super Admin** เท่านั้นที่เลือกยกเลิก/ลบถาวรแทนใครก็ได้ทุกใบ (รวมถึงใบที่อนุมัติ/ไม่อนุมัติไปแล้ว)
   - บุคคลอื่น (รวมถึงผู้อำนวยการ) เลือกยกเลิกได้เฉพาะใบลาของตัวเองที่ยังอยู่ในสถานะ "รอพิจารณา" เท่านั้น จะยกเลิกแทนคนอื่นไม่ได้
   - ปรับ `firestore.rules` ให้ Super Admin แก้/ยกเลิกแทนใครก็ได้ทุกกรณี, ผู้อำนวยการพิจารณาได้เฉพาะอนุมัติ/ไม่อนุมัติ (ยกเลิกแทนคนอื่นไม่ได้แม้เป็นผู้อำนวยการ), เจ้าของใบลายกเลิกได้เฉพาะใบตัวเองตอนยังรอพิจารณา ตรงกับสิทธิ์ที่ UI บังคับไว้
3. **ฟอร์มยื่นใบลา**: เพิ่มช่อง "มอบหมายงานในหน้าที่ให้" เป็นดรอปดาวน์ดึงรายชื่อจากทำเนียบบุคลากร (เลือกผู้รับมอบงานระหว่างลา) บันทึกไว้ในใบลาเพื่อพิมพ์ลงแบบฟอร์ม
4. **ใบลา PDF ปรับตามตัวอย่างที่แนบใหม่ทุกจุด**:
   - ตัดโลโก้ รพ.สต. ออกจากหัวแบบฟอร์มทุกใบ
   - เพิ่มส่วน "คำสั่ง...มอบหมายการทำงานในหน้าที่ให้...เป็นผู้ดำเนินการแทน" พร้อมช่องเซ็นชื่อ "ผู้มอบงาน" (ชื่อผู้ทำใบลา) และ "ผู้รับมอบงาน" (ชื่อที่เลือกจากช้อยข้อ 3) ต่อท้ายลายเซ็นผู้ยื่นใบลาในทุกแบบฟอร์ม
   - ช่อง "ผู้ตรวจสอบ" เซ็นชื่อ-ตำแหน่งไว้ล่วงหน้าเป็น "นางสาวพิไลวรรณ กุลมินทร์ / นักวิชาการสาธารณสุขชำนาญการ" พร้อมวันที่เติมให้อัตโนมัติตามวันที่เริ่มลาของใบนั้น (ไม่ต้องกรอกเอง)
   - ช่อง "ความเห็นของผู้บังคับบัญชา" เซ็นชื่อ-ตำแหน่งไว้ล่วงหน้าเป็นบุคคลเดียวกันเช่นกัน
   - ช่อง "เรียน" คำนวณอัตโนมัติ: ใบลาของนายพงศกร แป่มจำนัก (ผู้อำนวยการ) → "เรียน ผู้อำนวยการกองสาธารณสุข", ใบลาของพนักงานคนอื่นทุกคน → "เรียน ผู้อำนวยการโรงพยาบาลส่งเสริมสุขภาพตำบลบ้านหนองสนม" ใช้ทั้งหน้าใบลาและหน้าบันทึกข้อความ
   - ตัดข้อความท้ายกระดาษ "พิมพ์จากระบบ NSN-PHC Management System เมื่อวันที่..." ออกทั้งหมด
   - **การลาทุกประเภท** (ไม่ใช่แค่ลาพักผ่อนเหมือนเวอร์ชันก่อน) ส่งออกเป็น PDF 2 แผ่นเสมอ: แผ่นที่ 1 = ใบลา, แผ่นที่ 2 = "บันทึกข้อความ" ขอส่งใบลาเพื่อพิจารณา จ่าหน้าตาม "เรียน" ข้างต้น และลงชื่อท้ายบันทึกด้วยชื่อผู้ขอลาเอง (ไม่ใช่ชื่อผู้บริหาร)
