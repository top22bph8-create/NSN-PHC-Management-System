# คู่มือใช้งาน: ระบบประเมินความพึงพอใจผู้รับบริการ (v150)

## 1) เริ่มใช้งานครั้งแรก (เจ้าหน้าที่)
1. เมนู **งานธุรการ → 📊 ประเมินความพึงพอใจ** → แท็บ **ตั้งค่า**
2. กด “ดึงรายชื่อหมู่บ้านจากข้อมูล JHCIS” (หรือพิมพ์เอง บรรทัดละ 1 หมู่บ้าน) → ตรวจประเภทบริการ → **บันทึกการตั้งค่า**
3. แท็บ **QR Code / ป้าย A4** (ต้องเปิดจากเว็บจริงบน GitHub Pages ไม่ใช่เครื่องทดสอบ) → “สร้าง/ดูตัวอย่างป้าย” → ดาวน์โหลด PNG หรือพิมพ์
4. **ทดสอบสแกนด้วยมือถือก่อนพิมพ์จำนวนมาก** แล้วลองส่งแบบประเมิน 1 ชุด ตรวจในแดชบอร์ด (ถ้าเป็นข้อมูลทดสอบ ให้ Super Admin ลบออกได้ใน Firebase Console)

## 2) ประชาชน
สแกน QR → เลือกประเภทบริการ/หมู่บ้าน → แตะคะแนน 6 ข้อ (ต้องครบ) → ข้อเสนอแนะ (ไม่บังคับ) → ส่งแบบประเมิน ไม่เก็บชื่อ/เลขบัตร บันทึกวัน-เวลาอัตโนมัติ

## 3) แดชบอร์ดและรายงาน
- ตัวกรอง: วันที่เริ่ม-สิ้นสุด, ประเภทบริการ, หมู่บ้าน (ทุกตัวเลข/กราฟ/ตารางเปลี่ยนตามตัวกรอง)
- สูตร: เฉลี่ยรายด้าน = ผลรวมคะแนนด้านนั้น ÷ จำนวนผู้ตอบด้านนั้น · เฉลี่ยรวม = ผลรวมทุกข้อ ÷ จำนวนคำตอบคะแนนทั้งหมด · ร้อยละพึงพอใจ = (คะแนน 4 และ 5) ÷ คะแนนทั้งหมด × 100 · ไม่มีข้อมูลแสดง “ยังไม่มีข้อมูล”/0
- ระดับ: 4.51–5.00 มากที่สุด · 3.51–4.50 มาก · 2.51–3.50 ปานกลาง · 1.51–2.50 น้อย · ≤1.50 น้อยที่สุด
- รายงาน: รายวัน/เดือน/ไตรมาส (ปีงบประมาณ ไตรมาส 1 = ต.ค.–ธ.ค.)/ปี(ปีงบประมาณ)/ประเภทบริการ/หมู่บ้าน/คะแนนรายด้าน/ข้อเสนอแนะ
- Export: Excel (รายงานที่เลือก หรือครบทุกรายงาน+ข้อมูลดิบ), CSV ข้อมูลดิบ, Excel ข้อเสนอแนะ, PDF (สรุป+กราฟ+ข้อเสนอแนะ) และพิมพ์

## 4) ความปลอดภัย
ประชาชนเขียนได้เฉพาะการสร้างคำตอบที่ผ่านการตรวจรูปแบบ (คะแนน 1–5 จำนวนเต็ม, ข้อความ ≤1,000 ตัวอักษร, เวลาจากเซิร์ฟเวอร์), อ่าน/แก้ไขข้อมูลผู้อื่นไม่ได้, ลบได้เฉพาะ Super Admin, มีช่องดักบอทและกันกดซ้ำ — หากพบสแปมหนักควรเปิด Firebase App Check เพิ่ม

## 5) Deploy
อัปโหลดโฟลเดอร์ `src`, `docs`, `README.md`, `firestore.rules` ขึ้น GitHub → รอ Actions → วาง `firestore.rules` ใน Firebase Console → Firestore → Rules → Publish (ไม่ต้อง deploy Functions)
